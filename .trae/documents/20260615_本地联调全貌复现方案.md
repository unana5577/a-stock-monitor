## 一、现状诊断（用一句话说）

**你重构了前端页面（`pages/`）和后端路由（`server/`），但线上的 8787 端口跑的还是旧版 `根 server.js`（6200 行大单体），新的 `server/server.js` 从来没有被激活过，而且新的 `server/api/*.js` 里数据文件路径全是错的。**

## 三、三个核心问题及根因

### 3.1 数据路径问题

**根因**：`server/api/*.js` 里用了 `path.join(__dirname, 'data/...')`，但 `__dirname` = `server/api/`，拼出来的路径是 `server/api/data/...` 而不是 `项目根/data/...`。

| 文件 | 错误示例 | 实际解析路径 | 正确路径 |
|------|---------|-------------|---------|
| `server/api/shared.js:55` | `path.join(__dirname, 'data/market/ai/report.jsonl')` | `server/api/data/market/ai/report.jsonl` ❌ | `data/market/ai/report.jsonl` |
| `server/api/overview.js:83` | `path.join(__dirname, 'data/market/minute/breadth-cache.jsonl')` | `server/api/data/market/minute/...` ❌ | `data/market/minute/breadth-cache.jsonl` |
| `server/api/overview.js:128` | `path.join(__dirname, 'data/index/minute/...')` | `server/api/data/index/minute/...` ❌ | `data/index/minute/...` |

**但 `server/context.js` 的路径是正确的**，因为它用 `path.join(__dirname, '..', 'data', ...)` → `__dirname`=`server/`，`..` 回到项目根。

这导致如果启动新的 `server/server.js`（8788），所有读本地文件的 API 几乎全部失效。

### 3.2 数据每天都在更新（需要持续从网络拉取）

这不是 bug，是设计如此。但现在有两个问题：
- 本地 `data/` 里只有最近几天的数据（今天是 6月15日，有 6/11-6/15 的分时数据）
- 缺历史数据时页面所有图表都是空的
- **可以一次性从服务器 rsync 整个 `data/` 目录到本地，解决历史数据问题**

### 3.3 旧代码冗余

| 冗余项 | 说明 |
|--------|------|
| `根 server.js` | 6200 行大单体，已被 `server/` 替代但仍在运行 |
| `public/` 目录 | 旧版单文件前端，已被 `pages/` 替代 |
| `data/` 散落文件 | `breadth-cache.json`、`calendar.json`、各种 `sector-*.csv`、`.bak` 文件 |
| `data/` 根目录下旧格式 `minute-*` / `archive-*` / `overview-history-*` | 和 `data/index/minute/`、`data/etf/minute/` 新目录混存 |

## 四、执行步骤（6 步完成）

### 步骤 0：从服务器拉数据到本地

**目的**：不需要本地重新下载，直接复用服务器累积的历史数据。

**操作**（在你 Mac 本地执行）：

```bash
# 用 rsync 把服务器 data/ 目录同步到本地（排除 .git）
rsync -avz --progress \
  --exclude '.git' \
  root@你的服务器IP:/opt/a-stock-monitor/data/ \
  /Users/una5577/Documents/trae_projects/a-stock-monitor/data/
```

**验收**：本地 `data/` 出现大量服务器上的历史文件，`ls data/etf/daily/sz159995/daily.jsonl` 有几百行数据。

### 步骤 1：修复 `server/api/*.js` 所有路径 BUG

**范围**：`server/api/shared.js`、`server/api/overview.js`、`server/api/etf.js`、`server/api/trade.js`、`server/api/astro.js`

**做法**：在每个文件开头定义 `ROOT`，所有硬编码 `__dirname` 改为以 `ROOT` 为基准。

```js
// 在每个 api/*.js 文件最前面（require 之后、module.exports 之前）加：
const ROOT = path.resolve(__dirname, '..', '..');
```

然后将所有 `path.join(__dirname, 'data/...)` 改为 `path.join(ROOT, 'data/...)`。

**注意**：`server/context.js` 本身路径正确，不需要改。但 `context.js` 中的函数被 install 到 `global` 后在 `api/*.js` 中直接调用时，函数内部的 `__dirname` 指向 `context.js` 所在的 `server/` 目录，这是对的。

**验收**：grep `server/api/` 下所有 `path.join(__dirname` 不再出现。

### 步骤 2：让新 `server/server.js` 监听 8787 端口（替代旧版）

**当前**：`server/context.js` 里 `PORT = process.env.PORT || 8788`
**改为**：`PORT = process.env.PORT || 8787`

**然后**：旧 `根 server.js` 改为 `server_old.js`（重命名保留备份）

**验收**：`node server/server.js` 启动后：
```bash
curl http://localhost:8787/health   # 返回正常 JSON
curl http://localhost:8787/api/snapshot/latest  # 返回快照数据（读本地文件）
```

### 步骤 3：修复所有页面 server.js 代理目标

**当前**：页面 server.js 都已经代理到 `http://127.0.0.1:8787` → ✅ 正确，无需改。

**但**需要验证：启动所有服务后，通过 Shell 页面 8780 能正常 iframe 加载各板块。

### 步骤 4：清理冗余文件

**删除 / 重命名**：

| 操作 | 文件/目录 | 原因 |
|------|----------|------|
| 重命名 | `server.js` → `server_old.js` | 大单体，已被替代，保留作参考 |
| 保留 | `public/` | 先不动，确认新页面全正常后再删 |
| 清理 | `data/` 根目录下的 `.bak` 文件 | 备份文件，不需要 |
| 不移除 | `data/` 根目录 `minute-*` / `archive-*` / `overview-history-*` | 这些是旧服务产出的数据，新服务也会读，暂时保留 |

### 步骤 5：全量启动验证

```bash
# 终端1：数据 API 层
node server/server.js           # → 8787

# 终端2：Shell 入口
node pages/shell/server.js      # → 8780

# 终端3：概览页
node pages/overview/server.js   # → 8781

# 终端4：ETF 页
node pages/etf/server.js        # → 8782

# 终端5：交易助手
node pages/trade/server.js      # → 8783

# 终端6：天时页
node pages/astro/server.js      # → 8784
```

打开 `http://localhost:8780`，检查四个 tab 页面数据是否正常展示。

### 步骤 6：部署到服务器

确认本地全部通过后，调用 `deploy-a-stock-monitor` 技能同步代码到服务器并重建 Docker。

## 五、风险与注意事项

1. **新 server/server.js 从未在线上的 8787 端口跑过**，需要先在本地验证所有 API 路由都有输出
2. **`server/api/shared.js` 中有一些路径用的是 `../../` 而非 `__dirname`**（如 `path.join(__dirname, '..', 'data', ...)`），这些也是错的（`server/api/../data` = `server/data/` 而不是项目根），一并修复
3. **不要改线上 8787 的 server.js**，等本地全部验证通过后，用 `deploy-a-stock-monitor` 技能推
4. **rsync 数据时排除 `.git/`、`node_modules/`、`__pycache__/`**，只同步 `data/`
