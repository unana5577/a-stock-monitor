# 天时 + 回测架构规划

## 一、总览

**目标**：以"八字/天时作为辅助风险过滤因子"的定位，打通"用户八字 → 本周风险预测报告 → 每日盘后AI校准 → 回测信号过滤 → 胜率对比统计"这条完整链路。

**八字定位**：只做风险预测辅助，不做主要买卖依据。回测中天时因子效果通过"有/无过滤的胜率差异"来量化。

**AI聊天定位**：天时预测校准 + 盘面矫正。AI 能读取每日落盘的日线/分钟线/涨跌家数等数据，在聊天中回答"今天盘面和天时预测是否一致"类问题。

### 阶段二：天时落盘缓存 + 盘面聚合快照

**目标**：天时数据不再每次实时算，改为落盘后读文件。盘面数据每日收盘后自动聚合为快照文件，供 AI 聊天读取。

#### 2.1 天时落盘缓存

**新增文件**：`treasolo/m1_astro_cache.py`

- `--start YYYY-MM-DD --end YYYY-MM-DD`：批量生成缓存
- `--day YYYY-MM-DD`：单日增量更新（默认当天）
- 输出目录：`data/m1/astro_cache/{YYYY-MM-DD}.json`
- 与 `m1_astro_calendar.py` 的区别：`astro_calendar` 是 API 实时算，`astro_cache` 是落盘文件供回测和 AI 直接读

**server.js 新增路由**：

| 路由 | 方法 | 用途 |
|------|------|------|
| `GET /api/m1/data/astro_cache?day=` | GET | 读单日缓存 |
| `POST /api/m1/data/astro_cache/build` | POST | 触发批量缓存构建 |

#### 2.2 盘面聚合快照

**新增文件**：`treasolo/m1_market_snapshot.py`

- 输入：`--day YYYY-MM-DD`（默认最近交易日）
- 逻辑：聚合以下落盘数据为一站式快照：
  - 宽基指数日线（`data/index/daily/` 取最近 3 天）
  - ETF 日线（`data/etf/daily/` 取最近 3 天）
  - 涨跌家数（`breadth-history.jsonl`）
  - 成交额（`market-amount-daily.jsonl`）
  - 生命周期（`lifecycle.json`）
- 输出：`data/m1/market_snapshot/{YYYY-MM-DD}.json`

**server.js 新增路由**：

| 路由 | 方法 | 用途 |
|------|------|------|
| `GET /api/m1/data/market_snapshot?day=` | GET | 读盘面快照 |

### 阶段三：周风险预测报告 + 每日盘后AI校准

**目标**：
1. 周风险日历可见
2. 每天收盘后 AI 自动对比"天时预测风险等级 vs 当天实际盘面走势"，产出校准报告

#### 3.1 周风险预测报告

**新增文件**：`treasolo/m1_weekly_risk.py`

**输入**：用户八字（含日柱）+ weekStart/End
**输出**：每日风险等级 + 风险简述 + 周末总结

**风险判定规则（纯规则引擎，不依赖 AI，确保可回测复现）**：

| 规则 | 条件 | 风险等级 |
|------|------|----------|
| 日柱相冲 | 流日与八字日柱地支六冲 | `high_risk` |
| 日柱相害 | 流日与八字日柱地支相害 | `high_risk` |
| 月相转换日 | phaseIndex 为 0(新月) 或 4(满月) | `neutral` |
| 月相极弱 | phaseIndex 为 7(残月) | `caution` |
| 正常 | 以上均不命中 | `normal` |

**server.js 新增路由**：`POST /api/m1/data/weekly_risk`

**前端改动**：天时 Tab 进入时若八字已录入则自动拉取；在"本周交易表"上方展示风险日历。

#### 3.2 每日盘后 AI 校准

**新增文件**：`treasolo/m1_astro_calibrate.py`

**核心逻辑**：
1. 加载昨天的天时预测数据（从 `astro_cache`）
2. 加载昨天的盘面快照（从 `market_snapshot`）
3. 调用百炼 DeepSeek-V3，喂入对比 prompt，让 AI 判断：
   - 预测风险等级 vs 实际盘面走势是否匹配
   - 偏差在哪（例如预测是 normal 但大盘大跌）
   - 是否有规律性的误判模式
4. AI 校准结果落盘：`data/m1/astro_calibration/{YYYY-MM-DD}.json`

**输入数据范围**：
- 当前阶段：读取最近 3 个交易日的预测 vs 实际（因为线上只保留 3 个交易日日线）
- 后续扩展：当线上日线保留天数增加后，改为读取 N 天滚动窗口

**校准结果格式**：
```json
{
  "date": "2026-06-11",
  "predictedRisk": "normal",
  "actualOutcome": {
    "marketDirection": "上涨",
    "indexPct": { "上证": 0.32, "深证": 0.51 },
    "breadth": { "up": 2100, "down": 1800 },
    "turnover": "8500亿",
    "summary": "大盘小幅上涨，涨多跌少"
  },
  "match": true,
  "deviationNote": null,
  "calibrationAdvice": null
}
```

**触发方式**：在 `runner.py` 的 `m0m1` plan 中新增步骤 `astro_calibrate`，排在 `daily_qa` 之后。每天收盘后 runner 自动跑。

**server.js 新增路由**：

| 路由 | 方法 | 用途 |
|------|------|------|
| `GET /api/m1/data/astro_calibration?day=` | GET | 读 AI 校准结果 |

#### 3.3 规则权重自动优化（优化学习）

**新增文件**：`treasolo/m1_astro_rule_optimizer.py`

**概念解释**：
- 每条风险规则自带"准确率计数器"
- 每天校准后，如果某条规则"命中但实际市场不一致"，该规则的误报数+1
- 积累足够天数（默认 20 个交易日）后，系统自动调整每条规则的风险等级权重
- 准确率低的规则自动降级（如 `caution → neutral`），准确率高的保持

**数据文件**：`data/m1/astro_rule_weights.json`

```json
{
  "updatedAt": "2026-07-15",
  "basedOnDays": 22,
  "rules": [
    {
      "id": "日柱相冲",
      "originalLevel": "high_risk",
      "hits": 8,
      "misses": 2,
      "accuracy": 0.80,
      "effectiveLevel": "high_risk",
      "adjusted": false
    },
    {
      "id": "日柱相害",
      "originalLevel": "high_risk",
      "hits": 3,
      "misses": 1,
      "accuracy": 0.75,
      "effectiveLevel": "high_risk",
      "adjusted": false
    },
    {
      "id": "月相转换日",
      "originalLevel": "neutral",
      "hits": 5,
      "misses": 2,
      "accuracy": 0.71,
      "effectiveLevel": "neutral",
      "adjusted": false
    },
    {
      "id": "月相极弱",
      "originalLevel": "caution",
      "hits": 3,
      "misses": 12,
      "accuracy": 0.20,
      "effectiveLevel": "normal",
      "adjusted": true,
      "reason": "准确率仅20%，残月日实际风险并不高，自动降级为normal"
    }
  ]
}
```

**"命中/误报"判定逻辑**：

| 预测等级 | 实际市场 | 判定 |
|----------|----------|------|
| `high_risk` | 大盘跌幅 > 1% 或 跌家数 > 涨家数*1.5 | 命中 ✅ |
| `high_risk` | 大盘平盘或上涨 | 误报 ❌ |
| `caution` | 大盘跌幅 > 0.5% | 命中 ✅ |
| `caution` | 大盘涨幅 > 0.5% | 误报 ❌ |
| `neutral` | 大盘涨幅或跌幅 < 0.5% | 命中 ✅ |
| `neutral` | 大盘涨跌幅 > 1% | 误报 ❌ |
| `normal` | 大盘没有大跌（跌幅 < 1.5%）| 命中 ✅ |
| `normal` | 大盘大跌（跌幅 > 1.5%） | 误报 ❌ |

**自动调整规则**：
- 准确率 < 30%：风险等级降两级（`high_risk → neutral`, `caution → normal`）
- 准确率 < 50%：风险等级降一级（`high_risk → caution`, `caution → neutral`）
- 准确率 >= 50%：保持原等级
- 准确率 >= 80% 且连续命中 > 10 次：可升级

**触发时机**：紧跟 `astro_calibrate` 步骤之后，每个交易日收盘后自动执行。如果累计交易日不足 20 天，跳过优化（不做调整）。

**`m1_weekly_risk.py` 改造**：读取 `data/m1/astro_rule_weights.json`，用 `effectiveLevel` 替代 `originalLevel` 来判定每日风险。

**`astro_signal_filter.py` 改造**：同样读取权重文件，用调整后的等级做回测过滤。

### 阶段四：天时接入回测

**目标**：回测脚本增加天时过滤开关，输出"有过滤 vs 无过滤"的胜率对比。

#### 4.1 天时信号过滤器

**新增文件**：`波段策略/astro_signal_filter.py`

**核心逻辑**：
1. 加载 `data/m1/astro_cache/{day}.json` 获取当日天时数据
2. 应用风险判定规则引擎，判断 riskLevel
3. `high_risk` → 不开仓、不加仓
4. `caution` → 仓位上限减半
5. `neutral` / `normal` → 无限制

#### 4.2 回测脚本改造

**改动文件**：`波段策略/backtest_ranged.py` 和 `波段策略/backtest_staged.py`

- 新增 `--astro-filter true/false`（默认 false，向后兼容）
- 报表增加对比行：`总收益/胜率/最大回撤(无天时)` vs `(有天时)` + `被过滤交易数`

## 六、决策记录

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 八字定位 | 辅助风险预测，不做主要依据 | 用户明确指示 |
| 干支计算方式 | 本地 `tyme4py` 纯算法 | 不需要网络，精度够，已在用 |
| 风险判定引擎 | 纯规则引擎（非 AI） | 回测需要可复现的判定逻辑 |
| 天时缓存 | 落盘 `data/m1/astro_cache/` | 回测和 AI 聊天直接读文件 |
| 盘面快照 | 收盘后聚合落盘 `data/m1/market_snapshot/` | AI 聊天不实时算，读快照文件 |
| AI 聊天上下文 | 注入八字+大运+dayAstro+盘面快照+校准结果 | 让 AI 有足够信息做盘面矫正 |
| AI 校准触发 | `runner.py` 收盘后自动跑 | 用户要求自动触发 |
| AI 校准数据窗口 | 当前 3 个交易日，后续扩展到 N 天 | 线上日线保留天数限制 |
| 回测兼容性 | `--astro-filter` 默认 false | 不破坏现有回测脚本 |
| 城市与风险 | 无关，不参与风险判定 | 城市仅用于真太阳时校正 |
| Prompt 加载方式 | 前端从 API 拉取后缓存 | 你改文件即生效 |
| 优化学习方式 | 自动权重调整 | 用户选择；系统自动统计规则准确率，低准确率规则自动降级 |
| 权重调整最小样本 | 20 个交易日 | 样本太少无统计意义 |
| 权重调整阈值 | <30%降两级, <50%降一级, >=80%可升级 | 保守调参，避免过度拟合 |
