# 天时实验模块整体规划评审

## 原始目标回顾（来自规划文档）

天时实验的初衷是四件事：

| # | 目标 | 说明 |
|---|------|------|
| 1 | **防止风险** | 识别高风险日（月相/干支/流年流月冲克等），作为交易的辅助过滤 |
| 2 | **板块回测** | 对不同 ETF 的五行取象做历史验证，找出哪类品种在什么天时下偏强/偏弱 |
| 3 | **AI 反馈闭环** | 每日盘后把预测 vs 实际交给 AI 校准，持续修正规则 |
| 4 | **特殊日查询** | 方便查某个干支日/月相日/节气日的历史表现（如最近查的丙午日/乙巳日） |

## 评估：当前路径是否合理？

### 做得好的

**回测部分很扎实** — 8 个脚本覆盖了月相/干支/五行/信号合成，从统计→逐次→信号合成，递进逻辑清晰。这是"防止风险"和"板块回测"的必要基础。

**取象用数据驱动** — 不是拍脑袋定的五行，而是先跑数据反推，再让用户修正。方法论对。

**特殊日查询已验证有效性** — 丙午日全跌、乙巳日全涨、农历十五2026年3/3回调——这些规律已经有统计显著性，可以提炼进风险规则。

### 不对齐的部分

**当前的工作重点偏向了"回测分析"，而原始规划的核心是"风险规则引擎"**。原始规划明确写了：

> "风险判定用纯规则引擎（不用 AI），保证回测可复现"

这意味着当前 8 个回测脚本产出的结论（如"壬水日新月0%反弹"、"乙木日满月后3天100%下跌"），应该被编码进一个**规则文件或配置表**，由引擎读取并输出每日风险等级——但这一步还没做。

**信号合成器停留在训练阶段** — 已经训练好了 r=0.41 的模型，但没有挂接到前端 API（`astro_predict` 端点缺失）。前端还在调 404。

**AI 校准闭环没建** — `八字/prompts.json` 里有 `calibration` 模板，但没有对应的 `m1_astro_calibrate.py` 脚本去跑"预测 vs 实际"的对比。

## 建议的优先级调整

| 优先级 | 做什么 | 对应目标 | 工作量 |
|--------|--------|----------|--------|
| **P0** | 补 `astro_predict` API 路由（接信号合成器） | 1,2 | 小 — 在 astro.js 加一条路由调 Python |
| **P1** | 把回测发现的显著规律编码为风险规则表 | 1 | 中 — 新建 JSON 配置文件 + 引擎 |
| **P2** | 建 `astro_review` API（每日盘后对比预测 vs 实际） | 3 | 小 |
| **P3** | 建 `天时信号过滤器`（接入 _波段策略） | 1 | 中 |
| **P4** | 每日 AI 校准脚本 | 3 | 中 |
| **P5** | 前端加"特殊日查询"工具（代替手写临时脚本） | 4 | 中 |
