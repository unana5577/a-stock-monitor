## 二、ETF数据需求

### 2.1 必需字段（日线）

| 字段名 | 数据类型 | 说明 | 用途 |
|-------|---------|------|------|
| date | string | 日期（YYYY-MM-DD） | 时间序列对齐 |
| open | float | 开盘价 | K线图、缺口分析 |
| close | float | 收盘价 | **核心价格**，所有计算的基础 |
| high | float | 最高价 | 波动分析 |
| low | float | 最低价 | 波动分析 |
| volume | float | 成交量（手） | 量比计算（备选方案） |
| amount | float | **成交额（万元）** | **资金热度计算（必需）** |
| pct | float | 涨跌幅（%） | 直接使用，避免重复计算 |

### 2.2 可选字段（日线）

| 字段名 | 数据类型 | 说明 | 用途 |
|-------|---------|------|------|
| turnover_rate | float | 换手率（%） | 活跃度分析（暂未使用） |

### 2.3 历史深度要求

- **最小值**: 60天（计算MA5/MA20/分位数）
- **推荐值**: 90-120天（容错空间）
- **回测需求**: 2025-05-19起（约300天）

### 2.4 分时数据需求

**时间粒度**：1分钟或5分钟
**时段要求**：
- 上午：09:30-11:30
- 下午：13:00-15:00

**必需字段**：
- time（时间）
- close（收盘价）
- volume（成交量）
- amount（成交额）

**用途**：实时监控、日线Fallback（当日日线未更新时）

## 六、数据质量要求

### 6.1 完整性

- **无缺失日期**: 交易日必须连续
- **无空值**: 核心字段（date/close/amount）不能为空
- **日期对齐**: ETF与指数数据日期必须一致

### 6.2 准确性

- **价格范围**: close > 0，价格变化合理
- **成交额**: amount > 0
- **涨跌幅**: pct在-20%至20%之间（ETF无涨跌停限制，但极端值需验证）

### 6.3 时效性

- **更新时间**: 每日15:30前完成
- **数据日期**: 必须包含最新交易日
- **过期检测**: 读取时验证day字段

## 八、计算需求说明

### 8.1 Alpha超额收益

**公式**：`Alpha = ETF涨跌幅 - 基准涨跌幅`

**数据需求**：
- ETF收盘价（5日/20日）
- 基准指数收盘价（5日/20日）

**周期**：5日、20日

### 8.2 MA斜率

**公式**：`(当前MA - 3日前MA) / 3日前MA * 100%`

**数据需求**：
- ETF收盘价
- MA窗口：5日、20日
- 历史深度：窗口+3天

### 8.3 乖离率风险等级

**公式**：`(收盘价 - MA5) / MA5 * 100%`

**数据需求**：
- ETF收盘价
- 60日历史数据（计算分位数）

**分位数点**：0.95, 0.80, 0.60, 0.40, 0.20, 0.05

### 8.4 资金热度

**优先方案**（真实成交额）：
```
热度占比 = (ETF成交额 / 全市场ETF成交额) * 100%
热度变化 = 今日占比 / 昨日占比
```

**备选方案**（量比）：
```
量比 = 当前成交量 / 近3日平均成交量
```

**数据需求**：
- ETF成交额/成交量（今日、昨日）
- 全市场ETF成交额（今日、昨日）

### 8.5 动能标签

**输入参数**：
- alpha_5（5日超额收益）
- ma5_slope（MA5斜率）
- close（收盘价）
- ma5（MA5值）

**判断逻辑**：
- 价格是否在MA5上方
- Alpha强度（>3%, 1-3%, -1-1%, <-1%）
- MA5斜率方向

## 十、注意事项

### 10.1 ETF代码格式

- **必须包含交易所前缀**：`sh`（上交所）或 `sz`（深交所）
- ✅ 正确：`sh512480`、`sz159995`
- ❌ 错误：`512480`（缺前缀）

**原因**: 数据源（AkShare Sina）需要前缀识别

### 10.2 成交额单位

- **ETF/指数成交额**: 万元
- **全市场ETF成交额**: 元（需换算）

### 10.3 交易日判断

- 数据不应包含周末、节假日
- 读取时需验证日期连续性
- 缺失交易日需标记并回补

### 10.4 数据验证

业务层读取数据后必须验证：
```python
# 1. 检查日期是否最新
warmup_day = warmup.get('day')
if warmup_day < get_latest_trading_day():
    print("⚠️ Warmup数据过期")

# 2. 检查数据完整性
for name, data in history.items():
    if not data or len(data) < 60:
        print(f"⚠️ {name} 数据不足60天")
```

## 十一、数据层对接规范

### 11.1 禁止事项

- ❌ 业务层禁止调用数据获取接口（如`_fetch_tencent_daily`）

| 层级 | 职责 |
