- 科创板指 (000688)
- 沪深300 (需确认)
- 中证2000 (需确认)

### 1.2 数据接口
**主接口**：`get_index_history(symbol, days=180)`
- **位置**：`fetch_sector_data.py:3046`
- **数据源**：AkShare多源fallback
  1. `ak.index_zh_a_hist()` - 东财指数历史
  2. `ak.stock_zh_index_daily_em()` - 东财指数日线
  3. `ak.stock_zh_index_daily_tx()` - 腾讯指数日线

**返回字段**：
```python
{
    "date": "YYYY-MM-DD",
    "open": 开盘价,
    "close": 收盘价,
    "high": 最高价,
    "low": 最低价,
    "volume": 成交量,
    "amount": 成交额,
    "pct": 涨跌幅(%)  # 部分数据源缺失
}
```

### 1.3 接口稳定性
- **风险等级**：⚠️ 中等风险
- **历史数据**：✅ 稳定，支持2015-05-27起始
- **实时更新**：⚠️ 延迟约5-10分钟
- **数据源**：3源fallback，稳定性较好
- **封禁风险**：低（AkShare开源库，接口分散）

### 1.4 缺失字段风险
- **pct字段**：部分数据源不提供涨跌幅，需自行计算 `(close-open)/open*100`
- **换手率**：指数数据无换手率字段
- **昨收价**：无昨收价字段，涨跌幅计算依赖open

## 四、分时数据 vs 日线数据

### 4.1 分时数据接口
**接口**：`get_etf_minute_data(code)`
- **位置**：`fetch_sector_data.py:3560`
- **数据源**：`ak.fund_etf_hist_min_em()` - 东财ETF分时
- **频率**：1分钟线
- **时间范围**：当日9:30-15:00

**返回字段**：
```python
{
    "date": "YYYY-MM-DD",
    "data": [
        {
            "time": "YYYY-MM-DD HH:MM",
            "price": 最新价,
            "volume": 成交量,  # 累计值
            "amount": 成交额    # 累计值
        }
    ],
    "prevClose": 昨收价  # ⚠️ 可能缺失
}
```

### 4.2 分时→日线聚合
**函数**：`minute_to_daily(etf_code, date)`
- **位置**：`data_maintenance.py:149`
- **用途**：当日15:00后，用分时数据生成当日日线

**聚合逻辑**：
```python
open_price = 分时第一笔价格
close_price = 分时最后一笔价格
high_price = max(所有分时价格)
low_price = min(所有分时价格)
volume = sum(所有分时成交量)  # ⚠️ 成交量是累计值，不能直接sum
amount = sum(所有分时成交额)  # ⚠️ 成交额是累计值
pct = (close_price - open_price) / open_price * 100
```

**⚠️ 字段差异风险**：
1. **成交量/成交额**：分时数据返回累计值，最后一笔即为总量，不能sum
2. **昨收价**：分时接口可能不返回昨收，导致pct计算错误
3. **开盘价**：分时第一笔可能不是9:30:00（延迟开盘）
4. **数据完整性**：分时数据可能缺失早盘或尾盘

### 4.3 日线 vs 分时字段对比

| 字段 | 日线 | 分时 | 聚合风险 |
|------|------|------|---------|
| open | ✅ | ⚠️ 第一笔可能延迟 | 中等 |
| close | ✅ | ✅ | 低 |
| high | ✅ | ✅ | 低 |
| low | ✅ | ✅ | 低 |
| volume | ✅ | ❌ 累计值，不可sum | 高 |
| amount | ✅ | ❌ 累计值，不可sum | 高 |
| pct | ✅（部分源） | ❌ | 高（缺昨收） |
| amplitude | ✅（ETF） | ❌ | 高 |
| turnover | ✅（ETF） | ❌ | 高 |

### 4.4 分时转日线建议
**场景1：盘中实时数据**
- 使用分时数据最后一笔作为"实时close"
- high/low取自当日分时极值
- ⚠️ 不要用sum聚合volume/amount

**场景2：盘后历史数据**
- 优先使用日线接口（字段齐全、数据准确）
- 分时数据仅作fallback（日线接口失败时）
- 聚合时需验证字段合理性

**场景3：当日数据对账**
- 用分时数据15:00收盘价验证日线接口close
- 差异>0.1%时，用分时数据覆盖日线

## 七、综合风险评估

### 7.1 数据源稳定性排名
1. **ETF日线**（东财） - ✅ 最稳定
2. **涨跌家数**（东财全市场） - ✅ 稳定

6. **期货数据**（新浪） - ⚠️ 较高风险

1. **ETF日线**（东财） - ✅ 字段最全（含pct/amplitude/turnover）
2. **大盘指数** - ⚠️ 部分缺失pct
3. **板块指数** - ❌ 缺失pct/amplitude/turnover
4. **分时数据** - ❌ 不可直接聚合为日线

### 7.3 关键风险点
1. **期货合约切换**：需手动维护主力合约代码
2. **板块BK代码**：腾讯特有格式，需手动维护映射表
3. **分时→日线聚合**：volume/amount不可直接sum，pct缺昨收

## 十、结论

### 数据系统能力总结
- **ETF数据**：✅ 字段齐全、接口稳定、支持历史回补
- **大盘指数**：✅ 多源fallback、历史数据完整
- **分时数据**：⚠️ 可用但需谨慎聚合，建议盘后用日线覆盖
- **期货数据**：⚠️ 需维护合约切换，谨慎使用
- **板块指数**：⚠️ 需维护BK代码表，字段不全
- **涨跌家数**：✅ 实时数据稳定，历史需定时保存

### 对业务层建议
1. **优先使用ETF数据**：字段齐全、质量高、有涨跌幅
2. **分时数据仅作实时参考**：盘后必须用日线数据覆盖
3. **期货数据需明确合约规则**：主力合约 vs 连续合约
4. **板块数据需维护代码表**：腾讯BK代码 vs ETF代码
5. **建立数据对账机制**：分时15:00 vs 日线接口，差异>0.1%需告警
