## 一、模块一：市场状态判断

### 1.1 输入数据源

| 数据文件 | 内容 | 读取函数 |
|----------|------|----------|
| `data/warmup/warmup-60.json` | 上证/沪深300 最近60日序列 | `_read_index_series()` |
| `data/market/breadth-cache.json` | 每日涨跌家数 | `_read_breadth()` |
| `data/market/daily/amount/daily.jsonl` | 每日全市场成交额 | `_read_volume_series()` |

**取指数优先级**：先取 `sh000001`(上证指数),不存在则取 `sh000300`(沪深300)。

### 1.2 中间计算变量

| 变量名 | 类型 | 计算方式 | 用于 |
|--------|------|----------|------|
| `index_series` | `[{date, close, pct}]` | warmup 中取指定指数序列 | 下一步 |
| `closes` | `[float]` | index_series 中提取 close 列 | MA/涨跌幅 |
| `ma20` | `[float]` | `_calc_ma(closes, period=20)` | 斜率计算 |
| `latest_idx` | `int` | `len(closes) - 1` | 取最新值下标 |
| `latest_close` | `float` | `closes[latest_idx]` | 当前收盘价 |
| `latest_ma20` | `float` | `ma20[latest_idx]` | 当前20日均价 |
| `pct_from_ma20` | `float` | `(latest_close - latest_ma20) / latest_ma20 × 100` | 价格相对MA20的偏离百分比 |
| `slope_val` | `float` | MA20 最近5个值的线性回归斜率 | MA20趋势方向 |
| `idx_pct_5d` | `float` | `(closes[-1] - closes[-6]) / closes[-6] × 100` | 指数近5日涨跌幅 |
| `idx_pct_20d` | `float` | `(closes[-1] - closes[-21]) / closes[-21] × 100` | 指数近20日涨跌幅 |
| `breadth_series` | `[{date, up, down}]` | 从 breadth-cache 读取 | 涨跌家数 |
| `up_days` | `int` | 近10日中 up > down 的天数 | 多头强度 |
| `down_days` | `int` | 近10日中 down > up 的天数 | 空头强度 |
| `vol_slope` | `float` | 近5日成交额的 (后半段均值 - 前半段均值) / 总均值 | 量能趋势 |

### 1.3 输出指标 (indicators)

| 字段 | 类型 | 取值范围 | 含义 |
|------|------|----------|------|
| `index_trend` | `str` | `"above_ma"` / `"near_ma"` / `"below_ma"` | 指数相对MA20的位置与方向 |
| `ma20_slope` | `float` | 通常 -0.5 ~ +0.5 | MA20的5日线性回归斜率 (正=向上,负=向下) |
| `breadth_up_days` | `int` | 0~10 | 近10日涨>跌的天数 |
| `breadth_down_days` | `int` | 0~10 | 近10日跌>涨的天数 |
| `volume_trend` | `str` | `"rising"` / `"flat"` / `"falling"` | 近5日成交额趋势 |
| `index_pct_5d` | `float` | 百分比 | 指数近5日涨跌幅 |
| `index_pct_20d` | `float` | 百分比 | 指数近20日涨跌幅 |

**index_trend 判定规则**：

```
pct_from_ma20 > +1.5% AND slope_val > 0  →  "above_ma"
pct_from_ma20 < −1.5% AND slope_val < 0  →  "below_ma"
其他                                     →  "near_ma"
```

### 1.4 状态分类规则（6维度打分）

| 信号维度 | 正向条件 (up_signals) | 负向条件 (down_signals) | 分值 |
|----------|-----------------------|------------------------|------|
| 指数趋势 | `index_trend == "above_ma"` → +1 | `index_trend == "below_ma"` → +1 | 1.0 |
| 涨跌家数 | `up_days >= 7` → +1 | `down_days >= 7` → +1 | 1.0 |
| 5日涨跌幅 | `pct_5d > +1.0%` → +1 | `pct_5d < −1.0%` → +1 | 1.0 |
| 20日涨跌幅 | `pct_20d > +3.0%` → +1 | `pct_20d < −3.0%` → +1 | 1.0 |
| 量能趋势 | `volume_trend == "rising"` → +1 | `volume_trend == "falling"` → +1 | 1.0 |
| MA20斜率 | `slope > 0.05` → +0.5 | `slope < −0.05` → +0.5 | 0.5 |

> **满分 5.5 分**。总分 < 3 → 震荡市；≥ 3 → 上升或下跌。置信度 = max(up, down) / 5.5。

### 1.5 硬编码阈值汇总

| 阈值常量 | 值 | 用途 | 位置 |
|----------|-----|------|------|
| `MA周期` | 20 | 移动平均周期 | `_calc_ma(period=20)` |
| `MA20偏离判断线` | ±1.5% | 区分 above_ma / near_ma / below_ma | `detect_market_state()` L202-206 |
| `斜率看涨阈值` | +0.05 | slope 高于此算做多信号 | `_classify_state()` L303 |
| `斜率看跌阈值` | −0.05 | slope 低于此算做空信号 | `_classify_state()` L305 |
| `5日涨跌阈值` | ±1.0% | index_pct_5d 分类线 | L288-291 |
| `20日涨跌阈值` | ±3.0% | index_pct_20d 分类线 | L293-296 |
| `涨跌家数看多阈值` | ≥7天 | 近10日 up>down 天数 | L283 |
| `涨跌家数看空阈值` | ≥7天 | 近10日 down>up 天数 | L285 |
| `量能看涨阈值` | >0.05 | vol_slope 判定线 | L232 |
| `量能看跌阈值` | <−0.05 | vol_slope 判定线 | L234 |
| `状态判定线` | ≥3 | up/down_signals 总分阈值 | `_classify_state()` L311-316 |
| `最小数据要求` | 25条 | index_series 不足此数默认震荡 | L177 |
| `历史记录上限` | 60条 | history 数组最大长度 | L350 |
| `状态缓存天` | 当日有效 | as_of 同天复用已存状态 | `get_effective_state()` L403 |

## 二、模块二：震荡市投资策略

### 2.1 标的池

| Symbol | 名称 | 板块 |
|--------|------|------|
| `sh512480` | 半导体ETF | 科技 |
| `sh515880` | 通信ETF | 科技 |
| `sh516510` | 云计算ETF | 科技 |
| `sh516010` | 游戏ETF | 科技 |
| `sh563530` | 商业航天ETF | 科技 |
| `sh562500` | 机器人ETF | 科技 |
| `sh515120` | 创新药ETF | 科技 |

> 共 7 只科技 ETF。每只目标仓位占比 = `base_ratio / 7` = 60% / 7 ≈ 8.57%。

### 2.2 阶段定义 (Phase)

```
idle  ──→  (未建仓, 等待震荡市信号)
building  ──→  (分批建底仓中, 目标 base_ratio=60%)
holding  ──→  (底仓完成, 等待套利/吸筹信号)
uptrend  ──→  (上升趋势已确认, 波段仓合并到底仓持有)
```

| 阶段 | 触发条件 | 允许的动作 |
|------|----------|-----------|
| `idle` | 默认状态 / 市场状态非"震荡" | 无 |
| `building` | 市场状态="震荡" AND `base_built_pct < base_ratio` | build_batch (分批建仓) |
| `holding` | 市场状态="震荡" AND `base_built_pct >= base_ratio` | take_profit / dip_buy |
| `uptrend` | 市场状态="上升" | merge_to_base (波段合并) |

### 2.3 可调参数 (config)

| 参数名 | 默认值 | 类型 | 含义 | 建议测试范围 |
|--------|--------|------|------|-------------|
| `base_ratio` | `0.6` (60%) | float | 底仓占总资金比例 | 0.4 ~ 0.8 |
| `batches` | `3` | int | 建仓批次数 | 2 ~ 5 |
| `batch_ratio` | `0.2` | float | 每批建仓比例 = base_ratio/batches | 跟随 batches 变化 |
| `sell_trigger_pct` | `5.0` | float | 单只涨幅触发套利阈值 (%) | 3.0 ~ 8.0 |
| `sell_ratio` | `0.10` (10%) | float | 每次卖出总仓位的比例 | 0.05 ~ 0.20 |
| `buy_trigger_pct` | `3.0` | float | 单只跌幅触发加仓阈值 (%) | 2.0 ~ 5.0 |
| `buy_ratio` | `0.10` (10%) | float | 每次买入总资金的比例 | 0.05 ~ 0.15 |
| `cooldown_days` | `1` | int | 同向操作冷却天数 (同标当日最多做一次) | 0 ~ 3 |
| `uptrend_merge` | `true` | bool | 上升趋势后是否合并波段仓到底仓 | true/false |

### 2.4 建仓规则 (build_batch)

```
触发：phase = building AND 该标已建批次数 < batches

单批金额 = total_capital × base_ratio / 7 / batches
单批份额 = int(单批金额 / price / 100) × 100  (取整到100股)

每执行一次 building_phase += 1
building_phase == batches → status 变为 "holding"
```

**举例**（总资金10万, 3批建仓, 半导体当前价1.50）：
- 单只目标 = 100000 × 0.6 / 7 = 8571 元
- 每批金额 = 8571 / 3 = 2857 元
- 每批份额 = int(2857 / 1.50 / 100) × 100 = 1900 股 (2850元)

### 2.5 套利规则 (take_profit)

```
触发：phase = holding AND pct_change ≥ sell_trigger_pct

盈亏计算 = (当前价 - 底仓均价) / 底仓均价 × 100
卖出金额 = 该标总市值 × sell_ratio
卖出份额 = int(卖出金额 / price / 100) × 100  (至少100股)

优先从 swing_lots (波段仓) 卖出, 不足再从 base_shares (底仓) 出
```

### 2.6 吸筹规则 (dip_buy)

```
触发：phase = holding AND pct_change ≤ −buy_trigger_pct AND position_ratio < base_ratio

买入金额 = total_capital × buy_ratio
买入份额 = int(买入金额 / price / 100) × 100  (至少100股)

新增份额记入 swing_lots (波段账户), 不改底仓成本价
```

### 2.7 合并规则 (merge_to_base)

```
触发：phase = uptrend AND swing_lots 非空

swing 总份额 = Σ swing_lots.shares
swing 总成本 = Σ swing_lots.shares × swing_lots.cost
底仓新均价 = (base_shares × base_avg_cost + swing总成本) / (base_shares + swing总份额)

合并后 swing_lots 清空, status → "uptrend"
```

### 2.8 单标持仓结构

每只 ETF 维护两套仓位 (底仓 + 波段仓)：

| 字段 | 类型 | 含义 |
|------|------|------|
| `symbol` | `str` | ETF代码 |
| `name` | `str` | ETF名称 |
| `target_pct` | `float` | 该标占总资金目标比例 (= base_ratio/7) |
| `base_shares` | `int` | 底仓股数 |
| `base_avg_cost` | `float` | 底仓均价 |
| `base_target_shares` | `int` | 底仓目标股数 (预留,未使用) |
| `swing_lots` | `[{shares, cost, entry_date}]` | 波段仓批次 (每笔吸筹记录) |
| `building_phase` | `int` | 已建批次数 (0~batches) |
| `last_price` | `float` | 最新价格 (从warmup读取) |
| `last_price_date` | `str` | 最新价格日期 |
| `last_signal` | `str` | 上一次信号类型 (buy/sell) |
| `last_signal_date` | `str` | 上一次信号日期 |
| `status` | `str` | idle / building / holding / uptrend |

## 附录：关键区别 — 两个策略不冲突

| 维度 | 波段策略 (m1_policy.py) | 震荡市策略 (ranged_strategy.py) |
|------|-------------------------|-------------------------------|
| 触发条件 | 动能信号 + 趋势状态机 | 市场状态 = 震荡 (用户确认) |
| 标的 | 9只 ETF (含资源) | 7只科技 ETF |
| 仓位结构 | 单一底仓 (60%/70%/100%) | 底仓(60%) + 波段仓(swing_lots) |
| 操作方式 | 趋势跟随进出 (右侧) | 震荡市网格 (涨卖跌买) |
| 状态机 | OUT→BUILDING→IN→COOLING | idle→building→holding→uptrend |
| 数据依赖 | lifecycle 信号 + MA20/M60 | 价格涨跌幅 + 仓位比例 |
| 决策输出 | ENTER/HOLD/CUT/EXIT | build_batch/take_profit/dip_buy/merge |
| 关系 | **互斥** (不同市场环境) | 不会同时触发同标的冲突建议 |
