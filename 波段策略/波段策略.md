# 波段策略（趋势跟随 · 清仓派 · 筑底试探）

> **策略定位**：3–6 个月 ETF 波段操作 / 趋势跟随 / 筑底试探 + 趋势确认 / 过热即清仓  
> **核心原则**：不强势不做 — 动能未达"偏强向上"不做买入动作  
> **标的池**：9 只 ETF（sh512400/sh512480/sh515120/sh515880/sh516010/sh516160/sh516510/sh562500/sh563530）  
> **底层信号**：基于现有 `treasolo/m1_sector_lifecycle.py` 的动能/资金行为/阶段输出（不改动原文件）

---

## 一、整体架构（4 层）

```
┌─────────────────────────────────────────────────────────────┐
│  Portfolio 层（前端 ui_m1.js — 仓位/金额/板块约束）          │
│  输入：Policy 输出 + simState(现金/持仓/板块上限)            │
│  输出：目标仓位、交易金额/份额、确认弹窗                    │
├─────────────────────────────────────────────────────────────┤
│  Policy 层（新增：波段策略/m1_policy.py — 波段状态机）       │
│  输入：Signal 日序列 + 持仓状态                              │
│  输出：trend_state / action / position_level / reason       │
├─────────────────────────────────────────────────────────────┤
│  Signal 层（已有：treasolo/m1_sector_lifecycle.py，不改）    │
│  输出：动能 / 资金行为 / 阶段 / 指标数据（每只ETF每日）     │
├─────────────────────────────────────────────────────────────┤
│  Feature 层（波段策略内独立计算）                             │
│  输入：日线 daily.jsonl                                     │
│  输出：MA/Alpha/AmountShare/Bias 等特征                     │
└─────────────────────────────────────────────────────────────┘
```

**设计原则**：
- 每层独立可验证——任何一层改动能单独回测
- Signal 层保持对"今天发生了什么"的解释性（**不改动原 lifecycle 代码**）
- Policy 层提供"基于连续性我该做什么"的可执行信号
- Portfolio 层只做资金分配与约束

## 二、核心原则：不强势不做

```
所有买入动作（筑底试探/趋势入场/补仓）的前置条件：
  动能 ∈ { "偏强向上", "强势向上" }

唯一例外：筑底试探仓允许在 "中性震荡" 时轻仓入场（阶段为磨底期/潜伏期），
  但仓位大幅限制（目标仓位 × 25%，且不超过总资金 5%）。
  不强势时筑底试探的止损更严格：5日内再创新低即清仓。
```

## 三、仓位生命周期（完整 7 档）

一个 ETF 从"完全不持有"到"满仓"再到"清仓"：

| 档位 | 执行仓位 | 触发条件 | 动作名 |
|------|----------|----------|--------|
| 0 | 0% | 无信号 | OUT |
| **1** | **目标仓位 × 25%** | 筑底信号（磨底期/潜伏期 + Bias∈[-5%,+3%] + 5日未创新低） | BUILD |
| **2** | **目标仓位 × 60%** | R1 趋势确认（热度连升3天 + 动能 ≥ 偏强↑ + 不过热） | ENTER |
| **3** | **目标仓位 × 100%** | 已持仓 + 补仓条件（MA20回调/信号升级/MA60回调） | TOPUP |
| 4 | **目标仓位 × 70%** | 动能从强势→偏强 或 资金行为=资金撤退 | CUT(轻) |
| 5 | **目标仓位 × 40%** | 动能从偏强→中性震荡 或 资金行为=加速赶顶 | CUT(重) |
| 6 | **0% → COOLING** | 动能弱势向下/偏强向下 / Bias≥0.9×Max / 衰退期 | EXIT |
| — | **止损减半** | 单标从持仓峰值回撤 ≥ 预警线 | STOP_WARN |
| — | **止损清仓** | 单标从持仓峰值回撤 ≥ 执行线 | STOP_EXIT |

> 目标仓位 = 基准仓位 × 信号强度系数 × 价格系数（见第五节 Portfolio 层公式）  
> 峰值 = 该 ETF 持仓期间的最高浮盈（买入后以收盘价计算）

## 四、Policy 层（波段状态机）

### 4.1 状态定义

| 状态 | 含义 | 允许的动作 |
|------|------|-----------|
| **OUT** | 空仓，无持仓 | 可进入 BUILD 或 ENTER |
| **BUILDING** | 筑底试探持仓中 | HOLD / CUT / EXIT（筑底失败） |
| **IN** | 正式持仓中 | HOLD / TOPUP / CUT / EXIT |
| **COOLING** | 清仓后冷却期 | NONE（禁止入场） |

### 4.2 入场规则

#### 【规则 R0】筑底试探：OUT → BUILDING

触发条件（**全部同时满足**）：

```
① 阶段确认：阶段信号 ∈ { "磨底期", "潜伏期" }
   // lifecycle 已有这两个阶段判定

② 价格区间收敛：Bias_20 ∈ [-5%, +3%]
   // 价格在 MA20 附近，未大涨大跌，底部结构形成中

③ 不创新低：近 5 个交易日最低价 > 近 10 个交易日最低价
   // 底部确认：短期低点不再下移

④ 不在过热区：Bias_20 < 0.9 × Bias_20_History_Max
```

**筑底试探仓** = 目标仓位 × 25%

**筑底失败快速止损**：进入 BUILDING 后，若 5 个交易日内再创新低（最低价 < 入场当日近5日最低价），立即清掉试探仓回到 OUT。

> **注意**：筑底试探仓允许在动能="中性震荡"时入场（阶段优先）。但仓位被严格限制。

---

#### 【规则 R1】趋势确认入场：OUT/BUILDING → IN

触发条件（**全部同时满足**）：

```
① 20 日资金热度连续抬升 ≥ 3 个交易日
   Amount_Share_MA20(t) > MA20(t-1) > MA20(t-2) > MA20(t-3)

② 当日热度高于 20 日均值
   Amount_Share_Change20(t) > 0

③ 动能方向健康（不强势不做）
   动能 ∈ { "偏强向上", "强势向上" }

④ 不在过热区
   Bias_20 < 0.9 × Bias_20_History_Max（仅当 Bias_20 > 0 时判断）
```

**仓位**：
- 若从 OUT 直接入场 → 执行仓位 = 目标仓位 × 60%（首仓）
- 若从 BUILDING 升级 → 执行仓位 = 目标仓位 × 60%（筑底试探仓在计算时已被折算，合并后不超过 60%）

---

#### 【规则 R1a-R1c】补仓：IN 内

已处于 IN 状态，出现以下任一条件 → 补至目标仓位 × 100%：

```
R1a — MA20 回调补仓：
  已持仓 + Bias_20 ≤ +3% + 动能未降级（仍 ≥ 偏强向上）

R1b — MA60 回调补仓：
  已持仓 + Bias_20 ≤ 0% + MA60 斜率 > 0 + 板块逻辑未破坏

R1c — 信号升级补仓：
  已持仓 + 动能从"偏强向上"升级为"强势向上"
```

**补仓底线**：条件不出现就不补，持有首仓 60% 直到出场信号。

---

### 4.3 出场规则

#### 【规则 R2】分级减仓：IN 内

```
R2a — 动能减弱（轻减仓，100% → 70%）：
  动能从"强势向上"降级为"偏强向上"
  或 资金行为 = "资金撤退"

R2b — 趋势转弱（重减仓，70% → 40% 或 100% → 40%）：
  动能从"偏强向上"降级为"中性震荡"
  或 资金行为 = "加速赶顶"
  或 Bias_20 ≥ 0.85 × Bias_20_History_Max（预过热）

R2c — 趋势破坏（清仓，→ 0% → COOLING）：
  动能 ∈ { "弱势向下", "偏强向下" }
  或 Bias_20 > 0 且 Bias_20 ≥ 0.9 × Bias_20_History_Max（过热）
  或 阶段信号 = "衰退期"
  或 combo 操作建议 ∈ { "果断清仓", "清仓离场" }

R2d — 恐慌清仓（→ 0% → COOLING）：
  资金行为 = "恐慌出逃"
```

清仓后进入 COOLING，`exit_reason` 记录为 `"overheat"` / `"trend_break"` / `"stage_bad"` / `"panic"`。

---

#### 【规则 R3】冷却：COOLING → OUT

##### R3a — 过热清仓后冷却（`exit_reason = "overheat"`）

```
时间门槛：清仓后满 3 个交易日
条件门槛：Bias_20 ≤ 0.6 × Bias_20_History_Max（仅正乖离判断；若已转负，直接满足）
两个门槛同时满足 → 状态转为 OUT
```

##### R3b — 趋势破坏清仓后冷却（`exit_reason ≠ "overheat"`）

```
时间门槛：清仓后满 3 个交易日
条件门槛：动能恢复为 "偏强向上" 或 "强势向上"
          且 Amount_Share_MA20 不再下降（MA20(t) ≥ MA20(t-1) 或当天抬升天数 ≥ 1）
两个门槛同时满足 → 状态转为 OUT
```

---

#### 【规则 S1/S2】止损（每只 ETF 自适应）

用每只 ETF 的 `Pct_P80`（日涨跌幅 80 分位值，lifecycle 已有）自适应计算止损线：

```
止损预警线 = min(Pct_P80 × 5, 12%)
止损执行线 = min(Pct_P80 × 8, 18%)
```

| ETF | Pct_P80 | 预警线 | 执行线 |
|-----|---------|--------|--------|
| 创新药 | 1.17% | 5.9% | 9.4% |
| 新能源 | 1.32% | 6.6% | 10.6% |
| 有色金属 | 1.36% | 6.8% | 10.9% |
| 机器人 | 1.42% | 7.1% | 11.4% |
| 半导体 | 1.51% | 7.6% | 12.1% |
| 云计算 | 1.69% | 8.5% | 13.5% |
| 游戏 | 1.82% | 9.1% | 14.6% |
| 通信 | 1.89% | 9.5% | 15.1% |
| 商业航天 | 2.63% | 12.0%(上限) | 18.0%(上限) |

```
S1 — 止损减仓（当前仓位 → 50%）：
  从该 ETF 持仓峰值回撤 ≥ 预警线

S2 — 止损清仓（当前仓位 → 0% → COOLING）：
  从该 ETF 持仓峰值回撤 ≥ 执行线
```

止损只在信号未触发 R2 出场时作为**最后防线**生效——正常情况下 R2 信号先于止损触发。

### 4.4 筑底失败快速止损

```
BUILDING → OUT（筑底失败）：
  入场后 5 个交易日内，最低价 < 入场当日近 5 日最低价
  → 清掉试探仓，回到 OUT
```

### 4.5 状态机伪代码

```python
def compute_policy(signals_today, state_yesterday):
    """
    signals_today: { 动能, 资金行为, 阶段信号, 指标数据, 操作建议 }
    state_yesterday: { trend_state, exit_reason, exit_date, entry_date,
                       position_level, peak_equity, building_entry_low }
    返回: { trend_state, action, position_level, reason, signal_strength, cooldown_left }
    """
    current_state = state_yesterday["trend_state"]
    ind = signals_today["指标数据"]
    momentum = signals_today["动能"]
    behavior = signals_today["资金行为"]
    stage = signals_today["阶段信号"]

    # === 止损检查（所有持仓状态通用）===
    stop_action = check_stop_loss(signals_today, state_yesterday)
    if stop_action:
        return stop_action

    # === OUT 状态 ===
    if current_state == "OUT":
        # 先检查趋势确认入场（优先级更高）
        if check_entry_r1(signals_today):
            return make_enter(signals_today)
        # 再检查筑底试探
        if check_entry_r0(signals_today):
            return make_build(signals_today)
        return stay_out()

    # === BUILDING 状态 ===
    elif current_state == "BUILDING":
        # 筑底失败检查
        if check_building_fail(signals_today, state_yesterday):
            return make_exit("building_fail", signals_today)
        # 趋势确认 → 升级到 IN
        if check_entry_r1(signals_today):
            return make_enter(signals_today)
        # 未破位，继续持有试探仓
        return make_hold_building(signals_today)

    # === IN 状态 ===
    elif current_state == "IN":
        # 先检查补仓
        topup = check_topup(signals_today, state_yesterday)
        if topup:
            return make_topup(signals_today, topup)
        # 分级出场检查
        cut = check_cut(signals_today, state_yesterday)
        if cut:
            return cut
        exit_type = check_exit(signals_today)
        if exit_type:
            return make_exit(exit_type, signals_today)
        return make_hold(signals_today)

    # === COOLING 状态 ===
    elif current_state == "COOLING":
        cooldown_days = trading_days_since(state_yesterday["exit_date"])
        if cooldown_days >= 3:
            release = check_cooldown_release(signals_today, state_yesterday)
            if release:
                return release
        return stay_cooling(cooldown_days)
```

## 五、Portfolio 层（仓位分配——前端）

### 5.1 "不强势不做"过滤

```
所有买入决策的前提：
  仅 action ∈ { BUILD, ENTER, TOPUP } 且 动能 ≥ "偏强向上"（筑底试探可放宽至中性震荡）
  信号强度 = 动能 ∉ {偏强向下, 弱势向下, 强势向下} 时才参与仓位计算
```

### 5.2 基准仓位计算

```
activeTargets = { sym: signal_strength }
// 过滤出 action ∈ {BUILD, ENTER, HOLD, TOPUP} 且 动能健康的标的

权重映射：
  强势向上 → weight = 1.0
  偏强向上 → weight = 0.5
  中性震荡(仅筑底) → weight = 0.25

baselineWeight = 1.0 / max(1, 标的总数)

targetWeight(sym) = baselineWeight × weight(sym) / Σweight
```

### 5.3 价格匹配系数

同样强信号，靠近均线性价比更高：

```
priceFactor = clamp(1.0 - (Bias20 / HistoryMax) × 0.5, 0.5, 1.0)
仅对 Bias20 > 0 应用；Bias20 ≤ 0 时 priceFactor = 1.0
```

### 5.4 仓位计算完整公式

```
step1: baselineWeight = 1.0 / nActive
step2: signalWeight = baselineWeight × strengthWeight / ΣstrengthWeight
step3: priceFactor = clamp(1.0 - (Bias20/HistoryMax)×0.5, 0.5, 1.0)
step4: targetWeight = signalWeight × priceFactor
step5: execWeight = targetWeight × positionLevel
```

### 5.5 板块上限约束

```
maxCategoryPct = 30%
若某板块仓位超过上限，等比例缩减该板块内所有标的的目标仓位。
```

### 5.6 现金约束

```
buyNotional = min((targetWeight × execLevel - currentWeight) × equity, cash)
buyNotional ≤ 0 → 不生成买入建议
```

### 5.7 调仓阈值

```
|targetWeight - currentWeight| < 5% → 不触发建议
```
