### 3. n8n工作流配置

**文件**: `n8n-workflows/data-monitoring-workflow-v2.json`

**工作流节点**:
1. ⏰ 定时触发（每5分钟）
2. 🌐 调用数据监控API
3. 📊 解析监控数据
4. ❓ 是否有异常？
5. ✅ 正常结束
6. 📝 记录异常日志

**特点**:
- 所有节点都是中文（带emoji）
- 每个节点都有详细注释
- 自动记录异常到 `logs/data-monitoring-errors.log`

## 📋 部署步骤

### Step 1: 确认服务器已重启

服务器应该已经自动重启并加载了新的API端点。

验证：
```bash
curl http://localhost:8787/api/data/monitoring
```

如果返回JSON数据，说明服务器正常运行。

---

### Step 2: 导入n8n工作流

1. 打开n8n界面: **http://localhost:5678**
2. 点击右上角 **"..."** 菜单
3. 选择 **"Import from File"**
4. 选择文件: **`n8n-workflows/data-monitoring-workflow-v2.json`**
5. 点击 **"Import"**

---

### Step 3: 激活工作流

1. 导入后，查看工作流节点
2. 点击工作流左上角的 **"Inactive"** 开关
3. 切换为 **"Active"** 状态

---

### Step 4: 测试工作流

1. 点击第一个节点（⏰ 定时触发器）
2. 点击右上角 **"Execute Workflow"** 按钮
3. 查看每个节点的执行结果
4. 确认最后一个节点返回成功

---

## 🎯 工作流执行逻辑

```
每5分钟
  ↓
调用 /api/data/monitoring
  ↓
获取：
  - 当前时间状态（📈 盘中 / ☕ 午休 / 🏁 收盘后 / 🌙 晚间 / 📅 休市）
  - 各数据源状态
  - 异常警告列表
  ↓
检查是否有异常
  ↓
有异常 → 记录到 logs/data-monitoring-errors.log
无异常 → 正常结束
```

## 📊 监控的数据源

| 数据源 | 检查内容 | 状态标准 |
|--------|---------|---------|
| ETF日线 | 9个板块ETF最新日期 | 今天=✅，昨天=⚠️，缺失=❌ |
| 指数日线 | 4个指数最新日期 | 今天=✅，昨天=⚠️，缺失=❌ |
| 分时数据 | 更新频率 | 盘中5分钟内更新=✅ |
| 市场快照 | 更新频率 | 盘中8分钟内更新=✅ |
| Warmup缓存 | 最新日期+记录数 | 今天+60条=✅ |
| Lifecycle | 最新日期+项目数 | 今天+9项=✅ |

---

## 🔔 异常处理

### 异常级别

- **❌ Error**: 文件缺失、数据为空、读取失败
- **⚠️ Warning**: 数据延迟、更新过慢

### 异常日志格式

```
2026-04-15 19:32:08 - 🌙 晚间

📊 数据源状态:
  ETF日线: ✅正常 (正常:9 延迟:0 失败:0)
  指数日线: ⚠️延迟 (正常:0 延迟:4 失败:0)
  分时数据: ❌ 文件缺失
  市场快照: ✅ (5分钟前)
  Warmup: ✅ (2026-04-15)
  Lifecycle: ⚠️ (2026-04-14)

⚠️ 异常列表:
  ⚠️ index_daily: 4个数据源落后
  ❌ minute: 分时数据文件缺失

──────────────────────────────────────
```
