**⭐ 优先级1：Warmup缓存（推荐）**

### 1.2 读取代码示例

**方案A：读取Warmup（推荐）**
```python
import json

def load_etf_data_from_warmup():
    """从warmup读取所有ETF数据（推荐）"""
    with open('data/sector-history-warmup-60.json') as f:
        warmup = json.load(f)

    # 验证数据新鲜度
    warmup_day = warmup.get('day')
    print(f"Warmup日期: {warmup_day}")

    # 读取各ETF数据
    history = warmup.get('history', {})
    for etf_name, data in history.items():
        if data:
            latest = data[-1]
            print(f"{etf_name}: 最新{latest['date']}, 收盘{latest['close']}")

    return history
```

**方案B：读取原始日线（备选）**
```python
import json
from pathlib import Path

def load_etf_data_from_files(etf_codes):
    """从原始日线文件读取（备选）"""
    data = {}
    for code in etf_codes:
        filepath = f'data/etf_daily/etf_{code}.jsonl'
        with open(filepath) as f:
            lines = f.readlines()
            records = [json.loads(line) for line in lines]
            data[code] = records
    return data
```

```
┌─────────────────────────────────────────────────────────────────┐
│                       ETF日线数据流程                            │
└─────────────────────────────────────────────────────────────────┘

【数据源】
  └─> AkShare Sina ETF专用接口
      └─> fund_etf_hist_sina(symbol=ETF代码)
          代码位置：fetch_sector_data.py:_fetch_akshare_sina_etf()

  └─> fetch_sector_data.py:_fetch_tencent_daily()
      └─> 检测规则：6位数字，5开头=上交所，1开头=深交所
          └─> 是ETF → 调用 AkShare Sina
          └─> 不是 → 调用腾讯API

  └─> fetch_sector_data.py:_save_etf_to_disk()
      └─> 文件路径：data/etf_daily/etf_${CODE}.jsonl
          格式：{"date":"2026-03-16","open":1.23,"close":1.25,...}

【回补策略】
  └─> 启动时自动执行
      └─> server.js:backfillMissingDataOnStartup()
          └─> 检查缺失日期 → 调用接口补充 → 追加到jsonl文件

【读取优先级】
  1. warmup缓存：data/sector-history-warmup-60.json (优先)
  2. 本地文件：data/etf_daily/etf_${CODE}.jsonl (次选)
  3. 网络请求：实时调用API (兜底)
```

## 四、数据排查流程

### 问题1：成交额分时数据缺失

**症状**：前端显示"无数据"或时间断档

**排查步骤**：
```
1. 检查文件是否存在
   ls data/volume-*.json

2. 检查文件内容
   cat data/volume-20260316.json

3. 检查定时任务是否运行
   搜索 server.js:4952 附近的定时器代码
   确认 isMarketOpenNow() 返回 true

4. 检查数据源
   访问 /api/snapshot 查看 sentiment.volume 是否有值

5. 检查文件权限
   ls -l data/volume-*.json
```

### 问题2：ETF日线数据过期

**症状**：ETF最新日期是几天前

**排查步骤**：
```
1. 检查本地文件最新日期
   tail -1 data/etf_daily/etf_512480.jsonl

2. 检查是否是交易日
   对照交易日历，确认缺失日期是否为周末

3. 手动触发回补（自动增量更新）
   python3 data_maintenance.py

4. 检查分时Fallback是否生效
   grep "source=minute" data/etf_daily/etf_*.jsonl

5. 检查启动时回补逻辑
   server.js:backfillMissingDataOnStartup()
```

**ETF日线更新流程（v2.2增量更新）**：
```
1. 计算缺失交易日
   ├─ 读取本地最新日期
   ├─ 判断最新可交易日（非交易时间到今天，交易时间到昨天）
   └─ 计算中间的缺失交易日列表

2. 尝试东财接口
   ├─ 请求东财日线数据（只请求缺失范围）
   ├─ 成功 → 写入日线文件（data/etf_daily/*.jsonl）
   └─ 失败 → 进入步骤3

3. 分时数据Fallback
   ├─ 从 warmup 或 minute_data 读取分时数据
   ├─ 聚合生成日线（第一分钟开盘，最后一分钟收盘）
   ├─ pct计算：基于昨收价（从昨日日线读取）
   └─ 写入日线文件（source=minute）

4. 同步更新warmup缓存
   ├─ 调用 warmup_proxy_files() 重新生成
   ├─ 读取所有ETF日线文件（data/etf_daily/*.jsonl）
   ├─ 生成 sector-history-warmup-60.json
   └─ 文件日期 = 最新可交易日
```

**warmup验证**：

### 问题3：warmup缓存过期

**症状**：启动时warmup文件日期过旧

**排查步骤**：
```
1. 检查warmup文件日期
   python3 -c "import json;print(json.load(open('data/sector-history-warmup-60.json'))['day'])"

2. 检查ETF日线文件是否最新
   tail -1 data/etf_daily/etf_512480.jsonl

3. 手动重新生成warmup（从ETF日线文件）
   python3 -c "
import sys
sys.path.insert(0, '.')
from fetch_sector_data import warmup_proxy_files
warmup_proxy_files(days=60)
"

4. 验证warmup同步
   检查warmup日期是否与ETF日线文件最新日期一致
```

**warmup自动更新时机**：
- data_maintenance.py运行后自动同步
- ETF日线更新完成 → 立即重新生成warmup
- 保证warmup与持久化数据一致

function isMarketOpenNow() {
  const date = new Date();
  const minutes = date.getHours() * 60 + date.getMinutes();

  const morning = minutes >= 570 && minutes <= 690;    // 9:30-11:30
  const afternoon = minutes >= 780 && minutes <= 900;  // 13:00-15:00
