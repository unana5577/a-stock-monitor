# M1 数据工作流调度时间表

## 1. 盘中高频（每 5 分钟）
- **触发任务**: `minute_fetch` (通过外部脚本或 n8n 定时触发)
- **动作**: 抓取四大宽基指数的最新价、涨跌幅、成交量/额，追加写入到对应的分时文件 `data/market/minute/<symbol>/<day>.jsonl`
- **目的**: 实时获取盘中价格与市场动态。

## 2. 盘后首发（交易日 15:01）
- **触发任务**: `m1_minute_to_daily.py` (M1-B: 分时转日线工作流)
- **动作**: 读取今天的分时文件最后一条记录，结合昨天的日线收盘价，计算出当天的最终 `pct`，并写入到底表 `data/m1/index/<symbol>/daily.jsonl` 中，将 `providerId` 标记为 `minute_to_daily`。
- **目的**: 极致实时，不需要等待官方结算，前端立刻能够显示当天的日线最终状态。

## 3. 晚间兜底（交易日 18:00）
- **触发任务**: `m1_backfill_index.py` (M1: 日线历史回补与验证)
- **参数**: `--apply-fix --write`
- **动作**: 从稳定接口 (如 `akshare.tx`) 请求官方结算的日线数据。比对本地底表。如果发现 15:01 写入的数据与官方结算数据有微小偏差（或因为网络原因完全缺失），则覆盖/补齐当天的日线记录，将 `providerId` 更新为 `hybrid(local_legacy + akshare.tx)`。
- **目的**: 第一道官方对账与修复防线。

## 4. 晨间确认（交易日 09:00）
- **触发任务**: `m1_backfill_index.py` (同晚间兜底)
- **参数**: `--apply-fix --write`
- **动作**: 再次请求官方接口，做最后一次校验。
- **目的**: 考虑到 18:00 时某些接口可能数据还未完全落盘或更新，早上 9 点开盘前的这一次请求可以 100% 确保昨天的日线数据已经成为绝对权威的历史记录，为今天的盘中计算提供准确的昨收（`prev_close`）基准。
