# ETF板块数据日期与接口优化方案

## 问题背景

### 当前问题
1. **日期理解不一致**
   - ETF日线数据最新到2026-04-13（昨天）
   - 但lifecycle显示"数据日期"为2026-04-14（今天）
   - 用户无法清楚知道数据的实际截止日期

2. **数据时效性困惑**
   - 盘中（9:30-15:00）：想看实时状态，但只有昨天数据
   - 盘后（15:00-17:00）：接口逐步更新，但不知道是否已更新
   - 晚间（17:00后）：应该有今日完整数据，但系统仍显示昨天

3. **前端显示缺失**
   - lifecycle的"阶段信号"、"资金行为"、"操作建议"等字段有数据但前端未正确显示

## 数据接口调研结果

### 现有接口能力

| 接口 | 数据内容 | 更新时间 | 优势 | 劣势 |
|------|---------|---------|------|------|
| **fund_etf_hist_sina** (东财) | 开盘、收盘、最高、最低、成交量、成交额 | 盘后15:30-17:00 | 数据完整、字段齐全 | 当日盘中无数据 |
| **fund_etf_hist_em** (腾讯) | 同上，且涨跌幅已计算 | 盘后15:30-17:00 | 同东财 | 同东财 |
| **stock_zh_a_spot** (新浪) | 全市场实时：最新价、涨跌幅、成交量、成交额 | 交易时间内实时 | 实时更新 | 只有股票，不含ETF |

### 关键发现
- **腾讯接口在17:50已能获取4-14当日数据**（之前测试验证过）
- **问题不在接口，在于系统使用策略**

## 解决方案设计

### 方案A：数据截止日期标注（推荐优先实现）

**目标**：让用户明确知道数据的实际截止日期

**实施步骤**：

1. **API层添加 `data_cutoff_date` 字段**
   ```javascript
   // /api/sector/lifecycle 返回结构增加
   {
     "day": "2026-04-14",           // 算法使用的日期（可能是今天）
     "data_cutoff_date": "2026-04-13", // 数据实际截止日期
     "items": [...]
   }
   ```

2. **计算逻辑**：
   - 遍历所有板块的日线数据，取max(date)
   - 如果max(date) < today，则data_cutoff_date = max(date)
   - 如果max(date) == today，则data_cutoff_date = today

3. **前端显示**：
   - 在"板块生命周期"卡片标题下方显示
   - 格式：`📅 数据截止至：2026-04-13 15:00`
   - 如果截止日期<今天，显示橙色提示："今日数据尚未更新"

**修改文件**：
- `fetch_sector_data.py` - get_sector_lifecycle函数返回值增加cutoff_date计算
- `server.js` - /api/sector/lifecycle透传cutoff_date
- `public/index.html` - 增加显示区域

### 方案B：智能数据源切换（进阶优化）

**目标**：根据时间段自动选择最优数据源

**时间段划分**：

| 时段 | 数据源策略 | 显示内容 |
|------|-----------|---------|
| **9:30-11:30** (早盘) | 使用昨日完整数据 + 新浪实时快照 | 昨日分析 + 实时涨跌幅 |
| **11:30-13:00** (午休) | 同早盘 | 同早盘 |
| **13:00-15:00** (午盘) | 使用昨日完整数据 + 新浪实时快照 | 昨日分析 + 实时涨跌幅 |
| **15:00-17:00** (盘后更新期) | 优先尝试腾讯接口获取当日，失败则用昨日 | 当日或昨日（带提示） |
| **17:00-次日9:30** (次日开盘前) | 使用腾讯接口获取当日完整数据 | 当日完整分析 |

**实施步骤**：

1. **创建 `fetch_etf_realtime.py`**
   - 功能：调用腾讯接口获取当日数据
   - 输入：ETF代码列表
   - 输出：当日OHLCV数据（如已更新）

2. **修改 `get_sector_lifecycle`**
   - 增加时段判断逻辑
   - 盘中时段：返回昨日完整lifecycle + 实时overlay
   - 盘后时段：尝试获取当日，失败则fallback昨日

3. **API响应结构调整**：
   ```json
   {
     "day": "2026-04-14",
     "data_cutoff_date": "2026-04-13",
     "data_status": "pending", // "current" | "pending" | "partial"
     "realtime": {
       "512400": {"price": 2.14, "pct": 0.47},  // 实时快照
     },
     "items": [...]  // 基于data_cutoff_date的分析
   }
   ```

**修改文件**：
- 新建 `fetch_etf_realtime.py`
- 修改 `fetch_sector_data.py` - get_sector_lifecycle
- 修改 `server.js` - /api/sector/lifecycle路由
- 修改 `public/index.html` - 增加实时数据展示

### 方案C：前端字段显示修复（紧急修复）

**目标**：让lifecycle的"阶段信号"、"资金行为"、"操作建议"正确显示

**问题排查**：
1. API返回的数据字段：✅ 正确（ETF名称、阶段信号、资金行为、操作建议等都有）
2. HTML模板定义：✅ 正确（index.html中有对应的字段引用）
3. 可能问题：数据绑定或样式问题

**修复步骤**：

3. **强制刷新测试**

**修改文件**：
