# 交易日历管理规范

> **版本**: v1.0 | **适用范围**: 全系统数据请求与展示

---

## 一、核心原则

1. **交易日优先**：所有时间序列数据按交易日对齐
2. **非交易日回退**：自动回退到最近交易日，明确标注日期
3. **禁止未来函数**：回测严格禁止使用未来数据
4. **T-1标注**：数据必须标注实际日期

---

## 二、交易日判断

### 2.1 判断规则

```
是交易日 = 非周六日 AND 非节假日
```

### 2.2 判断优先级

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | 交易日历API | 实时判断 |
| 2 | config/holidays.json | 本地节假日配置 |
| 3 | 规则计算 | 周末判断 |

**当前实现**：`server.js` → `isTradingDay()`

## 三、各时段处理

### 3.1 时段划分（北京时间为准）

| 时段 | 时间范围 | 请求策略 | 数据展示 |
|------|---------|---------|---------|
| 盘前 | 9:30前 | 停止 | 昨日数据 |
| 上午 | 9:30-11:30 | 60秒刷新 | 实时数据 |
| 午休 | 11:30-13:00 | 停止 | **保留上午数据（不回退）** |
| 下午 | 13:00-15:00 | 60秒刷新 | 实时数据 |
| 收盘后 | 15:00-次日9:30 | 停止 | 当日完整数据 |
| 周末 | 周六/日全天 | 停止 | 回退到最近交易日 |
| 节假日 | config/holidays.json | 停止 | 回退到最近交易日 |

### 3.2 判断代码

```javascript
function getTradingPeriod() {
  const now = new Date();
  const hour = now.getHours();
  const minute = now.getMinutes();
  const weekday = now.getDay();

  // 周末
  if (weekday === 0 || weekday === 6) return 'weekend';

  const time = hour * 60 + minute;

  if (time >= 570 && time <= 690) return 'morning';      // 9:30-11:30
  if (time > 690 && time < 780) return 'lunch-break';    // 11:30-13:00
  if (time >= 780 && time <= 900) return 'afternoon';    // 13:00-15:00
  if (time < 570) return 'pre-market';                    // 盘前
  return 'after-close';                                   // 收盘后
}

function isInTradingTime() {
  const period = getTradingPeriod();
  return period === 'morning' || period === 'afternoon';
}
```

## 四、T-1数据标注

### 4.1 标注规范

所有API响应必须包含以下字段之一：

| 字段 | 适用场景 | 示例 |
|------|---------|------|
| `asof` | 快照、汇总数据 | `{"price": 1.23, "asof": "2026-03-08"}` |
| `date` | 日线、历史数据 | `[{"date": "2026-03-08", "close": 1.23}]` |

### 4.2 前端展示

- 页面顶部显示："数据截至：YYYY-MM-DD"
- 禁止在非交易日使用"今日"、"昨天"等模糊表述

## 五、缓存策略

### 5.1 缓存键设计

```
缓存键 = 数据类型 + 日期 + 参数
```

### 5.2 缓存时长

| 数据类型 | 缓存时长 | 失效条件 |
|---------|---------|---------|
| 快照 | 60秒 | 交易时段持续更新 |
| 分钟线 | 2秒 | 交易时段持续更新 |
| 日线/历史 | 永久 | 收盘后首次更新 |

### 5.3 请求去重

```javascript
const pendingRequests = new Map();

async function deduplicatedFetch(url) {
  if (pendingRequests.has(url)) {
    return pendingRequests.get(url);
  }
  const promise = fetch(url).then(data => {
    pendingRequests.delete(url);
    return data;
  });
  pendingRequests.set(url, promise);
  return promise;
}
```

## 六、数据对齐

### 6.1 对齐规则

- **基准**：交易日
- **缺失处理**：
  - 原始价格：不填充，保留NaN
  - 指标中间序列：可向前填充（如MA5计算）
  - 展示数据：使用最近可用值

### 6.2 严格禁止

- ❌ 向后填充（引入未来数据）
- ❌ 用均值填充（数据失真）
- ❌ 回测中使用未来数据填充

## 七、常见问题

### 7.1 数据加载到错误日期

**排查**：
1. 检查config/holidays.json是否完整
2. 检查isTradingDay()逻辑
3. 检查API响应的asof字段
4. 检查前端定时器是否在非交易时段停止

**解决**：更新holidays.json，加asof字段，添加日志

### 7.2 数据重复请求

**原因**：前端定时器频繁触发、多个Tab同时请求

**解决**：实现请求去重、添加交易时段判断
