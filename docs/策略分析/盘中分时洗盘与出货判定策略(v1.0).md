# 盘中分时洗盘与出货判定策略 (v3.0 极简三维版)

> **版本**: v3.0
> **核心理念**: 回归交易本质，只看【价格（涨/跌/横）】+【时间（>1小时）】+【资金（放/缩量）】。摒弃复杂形态，用最直白的数据定义盘中状态。

---

## 一、 量化特征定义 (客观观测指标)

### 1. 价格空间 (Price Zone)
反映当前价格的绝对涨跌水位。极值由该 ETF 过去 120 天日线数据动态生成（如 P80 为强势极值，P10 为弱势极值）。

| 状态标签 | 触发条件 | 含义 |
| :--- | :--- | :--- |
| **强势上涨** | 当前涨幅 `pct` > 强势极值 (`P80`) | 涨幅极大，进入可能的高潮派发区 |
| **正常上涨** | `1%` < 当前涨幅 `pct` <= 强势极值 (`P80`) | 温和推升，安全的赚钱效应区 |
| **横盘** | `-1%` <= 当前涨幅 `pct` <= `1%` | 水面附近的窄幅震荡，多空胶着 |
| **正常下跌** | 弱势极值 (`P10`) <= 当前跌幅 `pct` < `-1%` | 日常回调，洗盘与承接的主要发生区 |
| **极端下跌** | 当前跌幅 `pct` < 弱势极值 (`P10`) | 跌幅超常，进入恐慌破位区 |

### 2. 时间沉淀 (Time Accumulation)
反映在当前状态下运行的时长（剔除早盘 30 分钟的无序波动）。

| 状态标签 | 触发条件 | 含义 |
| :--- | :--- | :--- |
| **持久** | 该状态维持时间 > 1 小时 (60 分钟) | 经过了充分换手，状态真实有效，非骗线 |
| **短暂** | 该状态维持时间 < 1 小时 | 状态未稳固，可能是脉冲或情绪宣泄 |

### 3. 资金热度 (Fund Heat)
反映该 ETF 当前盘中成交量相对其昨日（T-1）常规水平的异常程度（替代换手率）。

> **计算逻辑说明**：
> 1. **基准设定**：以该 ETF **昨日（T-1）的成交量（Volume_T1）**作为直接对比基准。
> 2. **盘中折算**：盘中某时刻（如 10:30）的当前成交量，需按照“已开盘时间占全天240分钟的比例”折算为**预估全天成交量（Est_Volume）**。
> 3. **量比判定**：`量比 = Est_Volume / Volume_T1`。通过量比来判定当下是放量还是缩量。

| 状态标签 | 触发条件 | 含义 |
| :--- | :--- | :--- |
| **放量** | 盘中预估量比 > 历史放量阈值 `P80` (如 > 1.5) | 资金极度活跃，换手剧烈或大单扫货 |
| **缩量** | 盘中预估量比 < 历史缩量阈值 `P20` (如 < 0.6) | 资金不关注，流动性降低，抛压极小 |
| **平量** | 介于两者之间 | 随大盘常规换手 |

## 二、 盘中判定矩阵 (核心规则)

通过组合【价格】+【时间】+【资金】，推导盘中交易判断。

### 矩阵 A：下跌区 (重点抓“洗盘”与“承接”)
*前提：价格处于【正常下跌】(-1% 到 极值之间) 或【极端下跌】*

| 价格空间 | 时间沉淀 | 资金热度 | 逻辑推演 | 最终判断 (盘中输出) |
| :--- | :--- | :--- | :--- | :--- |
| **正常下跌** | **持久** | **放量/平量** | 跌超1%但未破底线，资金在持续接盘 | **低位承接有力 (震荡洗盘)** |
| **正常下跌** | **持久** | **缩量** | 跌超1%后横盘运行，成交显著萎缩，流动性下降 | **缩量横盘抗跌 (洗盘中继)** |
| 正常下跌 | 短暂 | 任意 | 趋势未明，承接不明 | **正常回落 (待确认)** |
| **极端下跌** | 任意 | **放量** | 跌破底线且放量，抛压集中释放，风险偏高 | **放量破位 (坚决规避)** |
| 极端下跌 | 任意 | 缩量/平量 | 跌破底线但成交清淡，流动性不足导致阴跌 | **缩量阴跌 (流动性丧失)** |

### 矩阵 B：横盘区 (水面博弈)
*前提：价格处于【横盘】(-1% 到 1% 之间)*

| 价格空间 | 时间沉淀 | 资金热度 | 逻辑推演 | 最终判断 (盘中输出) |
| :--- | :--- | :--- | :--- | :--- |
| **横盘** | **持久** | **放量** | 水面附近长时间拉锯且放量换手，多空分歧加剧 | **放量横盘分歧 (多空激战)** |
| **横盘** | **持久** | **缩量** | 水面附近长时间窄幅震荡，成交清淡，方向未明 | **缩量窄幅震荡 (方向未明)** |
| 横盘 | 短暂 | 任意 | 水面附近窄幅震荡 | **平盘震荡** |

### 矩阵 C：上涨区 (重点抓“逼空”与“出货”)
*前提：价格处于【正常上涨】(1% 到 极值之间) 或【强势上涨】*

| 价格空间 | 时间沉淀 | 资金热度 | 逻辑推演 | 最终判断 (盘中输出) |
| :--- | :--- | :--- | :--- | :--- |
| **正常上涨** | **持久** | 任意 | 温和推升且持续，趋势相对健康 | **温和上涨 (主升延续)** |
| 正常上涨 | 短暂 | 任意 | 上行刚形成，仍需确认 | **盘中拉升 (待确认)** |
| **强势上涨** | **持久** | **放量** | 高位放量但价格滞涨，兑现压力增大 | **高位放量滞涨 (警惕派发)** |
| **强势上涨** | **持久** | **缩量/平量** | 高位缩量且价格坚挺，抛压有限 | **缩量强势逼空 (高位锁仓)** |
| 强势上涨 | 短暂 | 放量 | 快速冲高并放量，短线回落风险增加 | **极值冲高放量 (警惕回落)** |

## 三、 事后 3 日闭环验证

盘中生成的判定标签，必须在随后 3 个交易日进行数据验收，以不断校准阈值的有效性：

1. **洗盘/承接类信号成功确认**：
   - 信号发出后，未来 3 个交易日内的**累计涨幅 > 绝对值(盘中最低跌幅) * 1.5**。
2. **派发/破位类信号成功确认**：
   - 信号发出后，未来 3 个交易日内多数收跌，或 3 日累计涨幅为负且未能收复 P20 防线。

## 四、 测算与测试推进路径 (开发与验证规划)

本策略的落地需严格遵循“数据回测 → 阈值校准 → 实盘模拟 → 正式上线”的闭环流程。

### 阶段 1：阈值字典的生成与固化
1. **任务**：编写盘后测算脚本 (`calc_intraday_thresholds.py`)。
2. **数据源**：读取 9 只核心 ETF 过去 120 天的真实日线数据 (`data/etf/daily/`)。
3. **输出**：生成包含所有“千人千面”变量的 JSON 字典（`P80`、`P10`、`amp_P20` 等），落盘至 `data/lifecycle/etf_intraday_thresholds.json`。

### 阶段 2：历史分时数据的静态回测 (核心验证)
1. **任务**：编写回测验证脚本 (`backtest_intraday_strategy.py`)。
2. **逻辑**：读取上述阈值字典，遍历历史分钟线数据，模拟盘中每 5 分钟的推演。
3. **验证指标**：
   - **命中率统计**：统计“低位承接有力”信号发出后，满足“3日成功确认标准”的胜率。
   - **时间参数 (T_hold) 调优**：回测 `T_hold` 在 45分钟、60分钟、90分钟 时的胜率差异，找到最佳的“熬人横盘时长”。
   - **极端个案排查**：人工抽查 10 个信号失败的案例（如提示洗盘但随后大跌），寻找特征漏洞。

### 阶段 3：实盘环境的沙盒运行
1. **任务**：将回测调优后的逻辑，集成到盘中实时聚合脚本中。
2. **逻辑**：盘中每 5 分钟输出实时判定快照 (`data/lifecycle/intraday/etf_snapshot.jsonl`)，但暂不推送到前端 UI。
3. **观察期**：运行 3-5 个交易日，由交易员（用户）在盘中对照 K 线，主观评估系统报出的标签是否符合实盘盘感。

### 阶段 4：前端 UI 字段对齐与接入
确认沙盒运行无误后，前端 UI 在盘中时段（09:30-15:00）切换数据源至 `intraday_snapshot.jsonl`。为复用现有的盘后卡片 UI（不修改 HTML 结构），字段将进行如下映射：

| 盘后卡片现有字段 | 盘中替换内容 (数据源映射) | 说明 |
| :--- | :--- | :--- |
| `位置名称` (如: 冰点期) | **`今日涨跌幅`** (如: -1.25%) | 盘中看绝对涨跌幅更直观。 |
| `操作建议` (如: 积极建仓) | **`盘中状态判断`** (如: 低位承接有力) | 右上角醒目位置展示 V3.0 矩阵推导出的最终标签。 |
| `动能` (如: 强势向上) | **`价格空间`** (如: 正常下跌) | 展示当前处于哪个水位区间。 |
| `资金行为` (如: 横盘整理) | **`时间与资金`** (如: 持久 · 放量) | 将时间沉淀与资金热度拼合展示。 |
| `热度占比` (如: 0.13%) | **`资金热度`** (如: 放量/平量/缩量) | 盘中只展示放缩量档位，不展示量比数值。 |
| `归因说明` (底部长文本) | **`逻辑推演`** | 展示矩阵推导的逻辑解释（如：“跌超1%但没破底线，且1小时以上资金持续接盘”）。 |
| *卡片分类池* | 与盘后一致（红/绿/黄） | 盘中不单独分 Buy/Hold/Sell/Wait，沿用盘后红/绿/黄池。 |

### 阶段 5：AI 提示词解耦
**AI 解说员**：AI 的提示词不再负责逻辑推演，而是直接读取卡片上已经定性的状态标签，生成一段宏观的“板块轮动与异动综述”。
