# 数据架构设计 - 三层分离

> **核心理念**：数据获取、计算、判断完全分离，每层独立可测

---

## 架构图

```
┌─────────────────────────────────────────────────────────────────┐
│                        第一层：数据接口层                        │
│  职责：纯粹的数据获取，不涉及业务逻辑                            │
└─────────────────────────────────────────────────────────────────┘

【分时数据】
  fetch_sector_data.py:get_etf_minute_data(code)
  └─> 返回：{ date: "2026-03-16", data: [...], prevClose: 1.23 }

【日线数据】
  fetch_sector_data.py:get_etf_daily_data(code, start_date)
  └─> 返回：[{ date: "2026-03-16", open: 1.2, close: 1.25, ... }]

【成交额数据】
  fetch_sector_data.py:get_market_volume(date)
  └─> 返回：{ "09:30": 12345678, "09:31": 23456789, ... }

【数据回刷】
  fetch_sector_data.py:backfill_data(type, code, start_date)
  └─> 规则：
      ├─ 判断交易日历
      ├─ 检查本地文件缺���
      ├─ 请求接口获取
      └─> 追加写入 jsonl

【数据验证】
  fetch_sector_data.py:validate_data(type, code, date)
  └─> 检查：
      ├─ 文件是否存在
      ├─ 数据是否完整（字段齐全）
      ├─ 日期是否连续
      └─> 返回：{ valid: true, missing: ["2026-03-14"] }

┌─────────────────────────────────────────────────────────────────┐
│                        第二层：计算层                            │
│  职责：纯函数计算，输入原始数据，输出计算结果                    │
└─────────────────────────────────────────────────────────────────┘

【成交额计算】
  calculator.js:calculateVolumeMetrics(currentVolume, historyVolume)
  └─> 输入：当前成交额, 历史成交额
  └─> 输出：{
        current: 12345678,
        yday: 23456789,
        delta: 1234567,
        pct: 5.2,
        estimated: 25000000,
        predicted: 1500000
      }

【价格计算】
  calculator.js:calculatePriceMetrics(priceData)
  └─> 输入：OHLC数据
  └─> 输出：{
        change: 0.025,
        pct: 2.5,
        highLow: 1.3,
        amplitude: 3.2
      }

【技术指标】
  calculator.js:calculateMA60(dailyData)
  calculator.js:calculateBias(price, ma60)
  calculator.js:calculateCorrelation(data1, data2)

┌─────────────────────────────────────────────────────────────────┐
│                      第三层：汇总与判断层                        │
│  职责：业务逻辑判断，生成信号和决策                              │
└─────────────────────────────────────────────────────────────────┘

【信号生成】
  strategy.js:generateSignal(metrics)
  └─> 输入：计算后的指标数据
  └─> 输出：{
        signal: "BUY",
        reason: "突破早盘高点",
        confidence: 0.8
      }

【风险评估】
  strategy.js:assessRisk(metrics)
  └─> 输出：{
        level: "MEDIUM",
        factors: ["乖离过大", "成交萎缩"]
      }

【汇总输出】
  server.js:/api/sentiment
  server.js:/api/sector/history_proxy
  └─> 整合三层数据，返回前端所需格式
```

## 排查流程（按层检查）

### 问题：成交额数据异常

**第一层检查（数据源）**：
```bash
# 检查数据接口
python3 -c "from fetch_sector_data import get_market_volume; print(get_market_volume('2026-03-16'))"

# 检查文件存在性
ls data/volume-*.json

# 检查数据完整性
python3 scripts/validate_data.py volume 2026-03-16
```

**第二层检查（计算）**：
```bash
# 检查计算函数
node -e "const calc = require('./calculator.js'); console.log(calc.calculateVolumeMetrics(...))"
```

**第三层检查（汇总）**：
```bash
# 检查API响应
curl http://localhost:3000/api/sentiment
```

## 文件结构

```
│   ├── fetch_sector_data.py  # 数据获取
│   ├── backfill.py           # 数据回刷
│   └── validator.py          # 数据验证
│
├── layer2_calculator/        # 第二层：计算
│   ├── calculator.js         # 纯计算函数
│   └── indicators.js         # 技术指标
│
├── layer3_strategy/          # 第三层：判断
│   ├── strategy.js           # 信号生成
│   └── risk_assessment.js    # 风险评估
│
└── server.js                 # 汇总API
```

---

## 核心原则

1. **第一层不计算**：只负责获取和存储数据
2. **第二层无状态**：纯函数，输入相同输出必相同
3. **第三层可替换**：业务逻辑变化不影响下层
