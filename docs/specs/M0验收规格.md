## 1) 系统不变量（≤10条）

1. **交易日口径唯一**：所有 `day/asOf` 均为北京时间（`Asia/Shanghai`）交易日（周末/法定节假日按 `config/holidays.json` 推导），禁止混用 UTC 或自然日。
2. **交易日推导可解释**：当 `--day` 非交易日时，Runner 必须回退到最近前一交易日，并在 RunJournal 中记录 providerId 与 asOf（用于审计“为什么是这一天”）。
3. **涨跌幅口径固定（交易所口径）**：`pct = (last - prevClose) / prevClose * 100`；其中 `prevClose` 为上一交易日收盘价，禁止使用今开或任意分钟点替代；所有展示/计算均以此口径为准。
4. **成交额血缘可追溯**：市场总成交额与全市场 ETF 成交额均必须能追溯到其采集接口/脚本与 asOf（来源/时间/回退原因），并能复算“ETF 成交额占比”。
5. **成交额两接口拼接（血缘固定）**：
   - 市场总成交额（日线）来自 `akshare.fund_etf_hist_sina(sh000001/sz399001)`（由 [backfill_market_amount_daily.py](file:///Users/una5577/Documents/trae_projects/a-stock-monitor/scripts/backfill_market_amount_daily.py) 生成 `data/market/market-amount-daily.jsonl`）。
   - 全市场 ETF 成交额（日线）来自 `akshare.fund_etf_category_sina(ETF基金)`（由 [market_snapshot_sina.py](file:///Users/una5577/Documents/trae_projects/a-stock-monitor/scripts/market_snapshot_sina.py) 生成 `data/market/etf-amount-daily.jsonl`）。
6. **落盘 + 元数据双写**：所有 M0 产物必须落盘，同时写入同目录 `.meta.json`（见第 3 节）；禁止仅返回内存结果或仅 stdout。
7. **RunJournal 三态**：`success | partial | failed` 三态固定；任一步 `failed` 则 run 为 `failed`；仅 warnings 不阻塞时为 `partial`；无 warning 且无失败为 `success`（与 [runner.py](file:///Users/una5577/Documents/trae_projects/a-stock-monitor/treasolo/runner.py) 语义一致）。
8. **Warnings 可枚举**：warnings 必须是结构化数组 `{code,severity,message,paths}`，禁止仅日志文本。
9. **保留 30 天**：`data/runs/**` 与 M0 产物至少保留最近 30 个交易日；清理脚本执行不得破坏“最近 30 天可复现”。

## 2) Runner 调用契约（n8n → Runner）

### 2.1 n8n 调用参数（必须传）

n8n 通过 Execute Command 调用 Runner，命令行参数固定为：

```bash
python3 -m treasolo.runner run \
  --plan m0m1 \
  --day <YYYY-MM-DD | empty> \
  --steps <comma-separated> \
  --trigger-type n8n \
  --trigger-source <workflowId/nodeId>
```

字段约束：
- `day`：可空；空时按不变量第 1/2 条由 Runner 推导。
- `steps`：只允许 M0 规范定义的 step 名称（见第 5 节 A/B）；不得传未知 step。
- `trigger-source`：必须能定位到 n8n 工作流与节点（例如 `n8n:workflow=xxx,node=yyy`）。

### 2.2 Runner 标准返回（stdout 或 HTTP 均同一 JSON）

Runner 必须输出单个 JSON（一行）作为唯一机器可读结果：

```json
{
  "runId": "20260416-152233-abcdef",
  "day": "2026-04-16",
  "asOf": "2026-04-16",
  "status": "success",
  "runJournalPath": "data/runs/2026-04-16/20260416-152233-abcdef.json",
  "outputs": [
    { "type": "file", "path": "data/runs/2026-04-16/..." }
  ]
}
```

约束：
- 必含字段：`runId,status,runJournalPath,day,asOf`。
- `outputs`：至少包含 `runJournalPath` 对应文件；其他产物可追加。
- 所有 path 使用仓库相对路径（由 n8n 自行拼装绝对路径）。

## 3) 落盘规范（产物路径 + meta 必填字段）

### 3.1 RunJournal 路径（固定）

- `data/runs/<day>/<runId>.json`
- `data/runs/<day>/<runId>-qa.json`（如产生 QA 报告）

### 3.2 M0 产物目录（固定）

- `data/m0/<day>/<runId>/...`：仅存放 M0 的 A/B 路径产物与最小对账报告。

### 3.3 Meta 文件（必有）

任意产物文件 `X` 必须存在对应 `X.meta.json`，且 meta JSON 必含字段：

```json
{
  "runId": "20260416-152233-abcdef",
  "step": "amount_stitch",
  "providerId": "akshare.fund_etf_category_sina",
  "asOf": "2026-04-16",
  "fallbackReason": null
}
```

约束：
- `providerId`：必须精确到“可定位的接口/脚本”（例如 `akshare.fund_etf_hist_sina` / `scripts.market_snapshot_sina`）。
- `fallbackReason`：无回退时为 `null`；回退必须给可读原因（例如 `holiday_shift` / `cache_used` / `upstream_timeout`）。

## 4) M0 验收 Checklist（必须能回答）

对任意一次运行（runId），系统必须能通过 `RunJournal + meta` 回答：
- 卡在哪一步（step name）？该 step 的 `status` 是什么？
- 用了哪个接口/脚本（providerId）？是否发生 fallback？原因是什么（fallbackReason）？
- `asOf` 是什么？是否与 `day` 一致？如果不一致，为什么？
- 产物在哪里（output path）？其 meta 是否齐全？
- 失败原因在哪（`error` 字段 + 相关 paths）？是否有 warnings（结构化）？

## 5) M0 仅验收两条路径（A/B）

### A) 成交额两接口拼接 → 总额落盘 → 血缘可追溯

**目标**：产出当日市场总成交额、当日全市场 ETF 成交额、以及 ETF 占比（可复算），并且血缘可追溯。

**Step 列表（固定顺序）**
1. `resolve_day`
2. `amount_fetch_market_total`
3. `amount_fetch_etf_total`
4. `amount_stitch`
5. `report`

**产物（必须落盘）**
- `data/m0/<day>/<runId>/amounts.json`
- `data/m0/<day>/<runId>/amounts.json.meta.json`

**amounts.json 最小字段**
```json
{
  "day": "2026-04-16",
  "marketTotalAmount": 0,
  "etfTotalAmount": 0,
  "etfSharePct": 0
}
```

### B) 分钟线 → 日线 → 最小对账报告落盘

**目标**：将指定标的分钟线聚合为当日日线，并输出最小对账报告（口径一致性与数据完整性）。

**Step 列表（固定顺序）**
1. `resolve_day`
2. `minute_load`
3. `minute_to_daily`
4. `minute_daily_reconcile`
5. `report`

**产物（必须落盘）**
- `data/m0/<day>/<runId>/minute2daily.json`
- `data/m0/<day>/<runId>/minute2daily.json.meta.json`

**minute2daily.json 最小字段**
```json
{
  "day": "2026-04-16",
  "symbol": "sh000001",
  "daily": { "open": 0, "high": 0, "low": 0, "close": 0, "amount": 0 },
  "reconcile": {
    "minutePoints": 0,
    "hasCloseBar": true,
    "pctOk": true,
    "notes": []
  }
}
```
