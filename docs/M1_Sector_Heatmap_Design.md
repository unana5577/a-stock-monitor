# M1 资金热度柱状图 (Sector Heatmap) 需求与执行文档

## 1. 核心业务目标
在前端展示一个支持“一级分类 -> 二级分类 -> ETF明细”三层下钻的资金热度图表。该图表需用单张**双向条形图**同时表达资金的“热度排名”与“涨跌方向”，帮助用户一眼看清当日资金正在爆炒（红）或抛售（绿）的核心标的。

## 2. 视觉设计范式（双向对称条形图）
- **X轴**：资金热度（`amount / total_etf_amount`），全正数。
- **Y轴**：分类名称（科技/资源等）或 ETF 名称。居中显示，作为红绿分界线。
- **左半区（绿色，跌）**：
  - 过滤条件：`pct < 0`
  - 排序方向：从左到右，热度由低到高（最靠近中间的柱子最高，代表“最核心的做空/出逃热点”）。
- **右半区（红色，涨）**：
  - 过滤条件：`pct > 0`
  - 排序方向：从左到右，热度由高到低（最靠近中间的柱子最高，代表“最核心的做多/追涨热点”）。
- **交互**：右上角提供“1级 / 2级 / 明细”面包屑导航，点击 Y 轴标签可向下钻取。

## 3. 数据流契约（前置依赖）
> **注意：后端计算逻辑由其他 Agent/脚本负责，本模块直接读取计算好的落盘文件。**

### 3.1 预期输入数据源
前置 Agent 需要每 5 分钟生成并覆盖写入一个 JSON 格式的盘中快照文件。
- **推荐文件路径**：`data/lifecycle/intraday/etf_hot_snapshot.json`（或追加在现有的 `etf_snapshot_YYYY-MM-DD.jsonl` 中）
- **必须包含的字段（单只 ETF 粒度）**：
  - `symbol`: ETF 代码（如 `sh512480`）
  - `pct`: 最新实时涨跌幅（如 `1.25`，可正可负）
  - `heat`: 资金热度（如 `0.15`，即 15% 的成交额占比，始终为正）
  - `category`: 一级分类（如 `科技`，从 `sector-proxy.json` 映射而来）
  - `sub_category`: 二级分类（如 `硬件`）

## 4. 执行步骤（Node.js 后端 + Vue 前端）

### Step 1: 后端接口开发 (`server.js`)
**目标**：新增 `/api/m1/data/heatmap` 接口，负责读取快照并进行层级聚合。
1. **读取文件**：读取前置 Agent 算好的快照文件（如 `etf_hot_snapshot.json`）。
2. **三层聚合计算**：
   - **Level 3 (ETF明细)**：直接使用原始数据的 `pct` 和 `heat`。
   - **Level 2 (二级分类聚合)**：以 `sub_category` 为维度。`heat` = 该二级下所有 ETF 的 `heat` 累加；`pct` = 该二级下代表性（或平均/热度加权）的 `pct`。
   - **Level 1 (一级分类聚合)**：以 `category` 为维度。聚合逻辑同上。
3. **返回结构**：
   ```json
   {
     "ok": true,
     "asOf": "14:30",
     "level1": [{ "name": "科技", "heat": 0.45, "pct": 1.2 }],
     "level2": { "科技": [{ "name": "硬件", "heat": 0.25, "pct": 1.5 }] },
     "level3": { "硬件": [{ "name": "半导体", "symbol": "sh512480", "heat": 0.15, "pct": 2.0 }] }
   }
   ```

### Step 2: 前端状态管理 (`public/ui_m1.js`)
**目标**：拉取数据并维护下钻状态。
1. **状态定义**：
   - `heatmapData`: 存储接口返回的全量数据。
   - `heatmapLevel`: 当前层级（1/2/3）。
   - `heatmapPath`: 路径记录（如 `[]`, `['科技']`, `['科技', '硬件']`）。
2. **定时拉取**：在 `onMounted` 中增加 `fetchHeatmapData()`，并加入 60 秒轮询队列。

### Step 3: ECharts 渲染与交互 (`public/index_m1.html` & `ui_m1.js`)
**目标**：实现双向对称条形图。
1. **DOM 占位**：在 `index_m1.html` 增加 `<div id="chart-heatmap"></div>` 容器及面包屑控制栏。
2. **渲染逻辑 (`renderHeatmapChart`)**：
   - 根据 `heatmapLevel` 和 `heatmapPath` 提取当前层级的展示数组。
   - **数据分发**：遍历数组，`pct < 0` 放入 `leftData`，`pct > 0` 放入 `rightData`。
   - **排序**：`leftData` 按 `heat` 升序，`rightData` 按 `heat` 降序。
   - **拼装坐标轴**：合并 `leftData` 和 `rightData` 形成完整的 Y 轴 `category` 数据。左侧 series 数据映射为负值（`-heat`）以画在零线左侧。
   - **颜色回调**：`itemStyle` 中根据 `pct` 正负返回红或绿。
3. **下钻事件**：
   - 监听 `chart.on('click', params => {...})`。
   - 如果当前是 Level 1，点击后将 `params.name` 加入路径，切换至 Level 2 并重绘。
   - 提供面包屑点击回退功能。

## 5. 验收标准
1. **视觉一致性**：中间高两边低，左绿右红，符合资金热度与方向的直觉。
2. **数据准确性**：一级/二级柱子的热度高度必须严格等于其子节点热度的数学累加。
3. **下钻流畅性**：点击图表 Y 轴类目能平滑切换层级，面包屑可正常返回。
